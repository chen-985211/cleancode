# 积木动作模型

## 文档地位

本文维护当前已实现终端积木与终端组合动作的功能意图、作用对象和语义边界。未来积木类型、通用动作描述器和混合组合只记录在 [UI 路线图](../../product/ui-roadmap.md)，不是本文的当前事实。

积木结构规则以[积木图模型](block-graph.md)为准；终端工作流运行语义以[终端依赖工作流](../run/terminal-workflow.md)为准；稳定用户交互以 [UI 契约](../../product/ui.md)为准。

## 动作定义

当前每个动作都必须由以下信息共同确定：

```txt
动作 = 功能意图 + 作用对象 + 可作用类型 + 用例入口 + 用户可见文案
```

| 概念       | 含义                                 | 当前示例                           |
| ---------- | ------------------------------------ | ---------------------------------- |
| 功能意图   | 动作要完成的业务目标                 | 运行启动命令、停止当前命令         |
| 作用对象   | 本次调用实际影响的对象               | 单个终端、组合内全部终端、活动流程 |
| 可作用类型 | 允许执行该动作的当前对象类型         | terminal、terminal group           |
| 用例入口   | 动作进入的应用层服务、用例或稳定端口 | 终端会话、积木图变更、工作流服务   |
| 可见文案   | 用户看到的名称和 tooltip             | 重开空终端会话                     |

任何动作如果没有明确作用对象，就不应展示或执行。图标和位置不是动作身份。

## 三类状态

终端动作必须区分：

| 状态类别 | Owner      | 当前示例                                 |
| -------- | ---------- | ---------------------------------------- |
| 配置     | BlockGraph | 启动命令、任务/服务配置                  |
| 当前执行 | Run        | 正在运行的命令、实际服务端点或工作流节点 |
| 运行环境 | Run        | 普通终端 PTY 会话                        |

因此，“启动命令”“停止当前命令”和“重开空终端会话”是三个不同动作：

- 启动命令：读取 BlockGraph 的不可变单终端启动计划，替换当前终端会话，并由 Run 执行已保存的命令与服务端口意图。
- 停止当前命令：向当前运行 PTY 发送 Ctrl+C，不关闭会话。
- 重开空终端会话：替换为新的交互式 shell，不执行启动命令。

## 单个终端与工作流

普通“启动命令”只作用于一个终端，不触发它的下游。“从此处运行流程”使用该终端及其所有后代生成不可变计划，拥有独立的调度、失败传播和停止规则。

直接启动、组合批量启动和工作流节点启动对受管服务复用同一个 Run `ManagedServiceLauncher`：端口分配、注入、监听所有权、实际端点和清理语义不能因入口不同而分叉。组合批量启动只负责对成员逐个调用单终端启动入口，仍不沿依赖连接扩散。

“停止当前命令”只向一个终端的当前 PTY 发送 Ctrl+C；“停止本次运行”则停止当前工作区的整个活动 `WorkflowRun`，包括尚未开始和已经运行/就绪的节点，不影响同画布的无关命令、其他工作区或其他项目。两者不得复用同一个作用范围。

## 类型化终端组合

`TerminalGroup` 只允许终端成员，是类型化批量操作对象，不是任意视觉分组，也不是工作流节点。

组合动作必须：

1. 只遍历该组合当前声明的成员 ID。
2. 对每个成员调用与单终端语义相同的入口。
3. 在文案中明确“组合”或“全部”，避免误认为只影响当前节点。
4. 不沿工作流连接扩散到组合之外的终端。
5. 解散时只删除组合，保留终端及其连接。

组合移动、成员和边界属于 BlockGraph；成员 PTY 与批量运行结果属于 Run。

## UI 与架构边界

- 表现层负责展示按钮、tooltip、禁用态和临时反馈，不拥有动作规则。
- 图结构动作进入 BlockGraph 应用层用例。
- 普通空终端运行环境动作进入 Run 的 `TerminalSessionService`；执行已保存启动命令进入 `LaunchTerminalCommandUseCase`。
- 依赖工作流动作进入 Run 的 `TerminalWorkflowService`。
- PTY、进程和系统命令只能通过 Run 应用层端口访问。
- 删除终端由 BlockGraph 用例通过 `TerminalRunLifecyclePort` 先硬清理精确 Run 作用域，再提交图结构变化；UI 不直接停止进程。
- Agent 控制台当前不是积木，不得套用终端动作或终端组合批量动作。

## 当前设计不变量

1. 动作必须明确作用对象；没有作用对象的动作不能执行。
2. 单终端动作不得意外影响同组合成员或工作流后代。
3. 组合动作只能影响组合内的终端成员。
4. 组合不是工作流；批量启动不等于依赖调度。
5. 运行配置、停止当前执行和重建运行环境必须保持语义区分。
6. UI 文案、tooltip、应用入口和测试名称必须使用一致的统一语言。
7. 三种启动入口不得绕过同一受管服务端口与实际端点语义。

## 维护规则

新增或更名当前动作时，必须同步功能意图、作用对象、应用入口、UI 文案和自动化测试。未来类型化动作声明、混合选择或其他积木动作必须先在 UI 路线图中确认，实际落地后再迁入本文。
