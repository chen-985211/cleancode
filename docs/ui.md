# UI 契约

## 文档地位

本文定义 cleancode 工作台长期有效的用户界面契约，包括信息架构、对象语义、关键交互不变量、状态反馈和视觉原则。

本文不是当前界面的截图说明、组件实现清单、版本验收记录或产品路线图。具体 DOM、CSS、图标、按钮排列和临时文案由当前实现与行为测试证明；尚未确认或尚未交付的方向统一记录在 [UI 路线图](ui-roadmap.md)，不得从路线图推导当前功能已经存在。

本文不重新定义架构规则、限界上下文、依赖方向或业务事实来源。相关规则以 [架构文档](architecture.md) 为准。

本文中的“必须”和“不得”表示稳定约束。用户确认的 UI 调整改变这些约束时，代码、测试和本文必须在同一任务中对齐；发现三者冲突时不得静默沿用旧描述。

## 产品定位

cleancode 的 UI 是画布优先的本地开发工作台。

用户进入项目后应直接看到工作画布，并能通过分支工作区、终端积木和 Codex Agent 控制台完成真实本地开发活动。界面不得退化为营销欢迎页、文件管理器、聊天应用或完整 IDE。

## 信息架构

工作台由两个顶层区域组成：

```txt
应用窗口
  ├─ 顶部标题栏：窗口身份与应用级设置入口
  └─ 工作区
      ├─ 左侧边栏：项目与分支工作区
      └─ 主工作区：积木画布
          ├─ 画布导航与操作
          ├─ 终端积木与终端组合
          └─ Codex Agent 控制台
```

主画布必须占据窗口的主要面积。Codex Agent 控制台位于画布内，不得恢复为固定右侧栏。

界面不得增加与当前开发工作无关的常驻区域，例如文件树、底部全局 Dock、营销式 Hero 或装饰性侧栏。新增长期区域前必须先确认它的用户目标和信息层级。

## 主题与外观

顶部标题栏必须提供唯一的主题设置入口。主题设置以不改变画布布局的右侧抽屉展示；抽屉打开时背景工作区不得继续接受交互，关闭后焦点必须回到入口。

主题偏好固定包含“系统”“浅色”和“深色”三种状态。首次使用默认为“系统”，用户选择必须跨应用重启恢复。选择“系统”时，有效主题必须跟随操作系统并响应运行中的系统主题变化；选择“浅色”或“深色”时，有效主题不得被系统变化覆盖。

主题必须覆盖应用标题栏、侧边栏、画布、终端积木、终端组合、Agent 控制台、小地图、菜单、表单、弹窗、提示和 xterm 内容。主题切换不得重建终端或 Agent 会话，也不得修改项目、工作区或画布业务状态。Agent xterm 已缓冲的原始真彩色输出必须保持为统一可读的主题外观，不得在切换后混合展示切换前后的明暗配色。

所有当前和后续 UI 必须通过统一语义颜色表达背景、表面、文字、边框、焦点和状态，不得在组件中建立绕过主题系统的独立配色。尚未提供的颜色预设、字体、圆角和密度选项不得以空分组、禁用项或占位内容出现在主题设置中。

## 分支工作区

分支工作区是用户理解项目开发状态的主要边界：

```txt
一个分支工作区 = 一个完整工作面
```

完整工作面包含该工作区的积木图、终端积木、终端会话和 Agent 会话。切换分支工作区时，这些内容必须一起切换，不得串用其他工作区的会话或画布状态。

默认工作区以 `main` 作为稳定工作区名称。`main` 可以绑定真实 Git 分支；绑定状态不得制造另一个并列的“默认工作区”条目。项目尚未初始化 Git 时，侧边栏必须以“Git 未初始化”替代虚假的分支名，并保留“默认工作区”身份；初始化后显示真实绑定分支。

Agent 对话以“项目 + 工作区 + 当前 Git 分支 + Agent 身份”为隔离范围。默认工作区名称保持为 `main` 时，检出不同真实 Git 分支仍然属于不同 Agent 对话；同一分支的不同 Agent 也不得串用对话。切回原分支必须为每个 Agent 恢复其已经持久化的对话绑定。

独立 worktree 是实现隔离的技术手段。UI 可以通过辅助信息表达工作区类型，但不得把 worktree 路径提升为主要用户概念。

归档分支工作区属于破坏性操作，必须二次确认并明确说明：归档会移除 worktree 目录但保留 Git 分支。归档当前工作区时还必须说明将先切回默认工作区。

## 左侧边栏

左侧边栏只承载项目和分支工作区导航，以及与它们直接相关的操作。

左侧边栏必须提供：

- 添加和移除项目。
- 项目列表与每个项目的分支工作区列表。
- 当前项目和当前分支工作区的明确选中状态。
- 创建、切换和归档分支工作区的入口。
- 在默认工作区选择或检出可用 Git 分支的入口。

项目名、分支名和工作目录等长文本必须安全截断或折行，不得撑破布局。工作区类型、当前状态和不可用原因必须通过文字、图标或辅助属性表达，不得只依赖颜色。

移除项目必须二次确认，并明确说明：该操作会从 cleancode 项目列表中移除项目并停止其终端和 Agent 会话，但不会删除本地项目目录或 Git 数据。

## 主画布

主画布是终端、终端组合和 Agent 控制台的空间工作面。

画布必须支持：

- 展示当前分支工作区的积木图。
- 创建、选择、多选、移动、调整大小和删除终端积木。
- 保存积木图、终端位置与大小，以及画布视口。
- 创建、选择、移动、折叠、展开和解散终端组合。
- 创建、展示、选择、重命名、移动、调整大小和移除 Codex Agent 控制台。
- 在重新进入工作面后恢复已经持久化的画布事实。

终端积木、终端组合和 Agent 控制台的整体选择只能由顶部标题区域触发；标题中的操作控件只执行自身动作，正文交互不得隐式选择整体。普通整体选择在三类对象之间必须互斥；终端多选只允许通过明确的多选操作形成。单击画布空白区域必须清除当前终端、终端组合和 Agent 的整体选择。终端积木和 Agent 控制台不要求预先选中，用户靠近任一角即可直接调整大小。三类对象的选中状态必须以克制的虚线边界和低亮度覆盖层表达，不得依赖高亮实线或大面积强色。

画布工具必须位于主工作区内。没有当前项目或桌面运行时不可用时，依赖真实项目、文件系统、PTY 或 Agent 的操作必须禁用或展示明确空状态。

浏览器预览只能用于展示界面，不得伪造真实项目、终端或 Agent 能力。

## 小地图

小地图是画布的空间导航视图，不是内容预览器。

小地图必须：

- 用简化图形表达已经纳入导航的画布对象，包括终端积木、折叠终端组合和 Codex Agent 控制台。
- 展示当前画布视口，并支持缩放、适应画布、收起、展开和视口移动。
- 支持从可导航缩略对象定位到对应画布对象。
- 用克制的状态差异表达选中、悬停、运行和失败，不得让状态色替代对象身份。

展开的终端组合以成员终端作为主要导航对象，不额外强调组合外框；折叠的终端组合以一个组合缩略块表达，并保留成员摘要语义。

Codex Agent 控制台在小地图中只显示中性的空间占位和身份。小地图不得展示终端输出、Agent 对话、授权内容、完整属性或文件内容。

## 终端积木

终端积木是在画布上承载交互式本地终端会话的运行对象。

终端积木必须支持：

- 显示名称、描述和未启动、运行中、已退出、失败等会话状态。
- 配置并执行启动命令。
- 输入命令并显示标准输出和标准错误。
- 停止当前命令。
- 重开空终端会话。
- 编辑信息、调整大小和删除。

终端会话的工作目录必须来自当前分支工作区对应的本地目录。

终端主要操作应直接可发现，低频会话管理动作可以进入更多菜单。图标按钮必须提供可访问名称或工具提示；编辑表单必须提供明确标签、输入提示、保存和取消。

### 启动命令语义

未配置启动命令时，启动入口必须引导用户完成配置。已经配置时，执行启动命令必须：

1. 终止该终端的旧会话。
2. 启动新的终端会话。
3. 清空旧的可见输出。
4. 向新会话写入且只写入一次启动命令。

启动过程必须防止重复触发。启动命令不得写入仍在运行的旧项目进程。

### 重开空终端会话语义

重开空终端会话必须替换旧会话、清空旧输出，并且不得执行已配置的启动命令。入口文案或工具提示必须明确这一差异。

## 终端组合

终端组合是只允许终端成员加入的类型化组合。它用于组织和批量管理开发命令，本身不创建新的 PTY，也不承载终端输出。

终端组合必须遵守：

- 有效组合至少包含两个终端成员。
- 组合动作只能影响该组合的终端成员。
- 解散组合只移除组合关系，必须保留成员终端。
- 折叠和展开只改变展示形态，不得改变成员关系或运行状态。
- 组合成员的运行状态属于成员自身，不得在组合头部重复制造聚合状态。

用户必须能够创建组合、编辑名称、折叠或展开、添加或移出成员、启动成员启动命令、停止成员当前命令、重开成员终端会话和解散组合。

组合编辑模式必须明确表达当前选择、可加入成员、不可加入成员、拖入、移出以及可能导致组合解散的结果。少于两个有效成员时，系统必须阻止形成组合或自动解散组合。

常用组合操作应保持可发现并按运行、成员管理和结构管理形成清晰分组。具体图标、按钮形态和排列属于可演进的表现细节，不是本文的稳定契约。

## Codex Agent 控制台

Codex Agent 控制台是画布内的本地 Codex CLI 交互工作面。它采用节点式画布交互，但不是普通终端积木，也不属于终端组合。

Codex Agent 控制台必须：

- 在紧凑头部只显示稳定 Agent 名称；Codex CLI 身份和当前分支工作区不得作为重复副标题常驻展示。
- 低频动作收纳在常驻可见的更多菜单入口中，不得依赖悬停后才显示。
- 支持双击 Agent 名称直接进行就地重命名。
- 承载真实 Codex CLI PTY 输入与输出。
- 支持选择、移动和调整大小。
- 在控制台内部滚动时只滚动 Agent 内容，不得触发外层画布缩放或平移。
- 展示并处理需要用户确认的 Agent 工具授权。
- 在 Agent 修改积木图后刷新当前工作面。
- 切换分支工作区时连接对应的 Agent 会话，不串用其他工作区状态。
- 完全退出并重新打开应用后，恢复当前项目、工作区和 Git 分支已经完成的 Codex 对话。
- 完全退出并重新打开应用后，恢复 Agent 数量、名称、位置和大小。

一个工作区允许拥有零个或多个 Codex Agent 控制台。新工作区首次进入时创建一个默认 Agent；用户移除最后一个 Agent 后必须保留空状态，不得静默重建。创建第二个及后续 Agent 时必须说明它们共享当前工作区目录、可能同时修改相同文件；需要文件级隔离时应使用不同 worktree 工作区。

每个 Agent 必须拥有稳定身份和独立的 Codex CLI PTY、输入输出、审批、MCP 会话及分支对话绑定。移动、选择、重命名或调整控制台大小不得重启或重复创建 Agent 会话。

移除 Agent 属于破坏性操作，必须确认并明确说明：系统会停止该 Agent、取消其未完成审批并删除 cleancode 中的 Agent 定义和对话绑定，但不会回滚项目文件、删除 Git 提交或影响其他 Agent。

Agent 控制台不得展示终端端口，不得加入终端组合，也不得进入普通终端积木的创建、删除、组合或批量运行流程。

正常状态必须保持静默：Codex CLI 已安装且会话正常运行时，不得常驻展示“已安装”“已连接”、版本号或同义状态卡。只有运行时不可用、检查中、未检测到 CLI、会话失败或会话结束等需要注意的状态，才显示一条紧凑辅助提示。

对话恢复失败时必须提供紧凑的“重试”和“新对话”动作。新对话只替换当前项目、工作区、Git 分支和当前 Agent 的恢复绑定，不得删除其他 Agent 或其他分支的对话。

Agent 身份与工作区构成紧凑头部，异常提示属于次要信息，终端输出占据主要面积。正常状态不得使用大面积成功色；警示色只用于需要处理的异常或授权状态。

本地 Codex CLI 必须通过应用层用例操作项目、分支工作区、积木图和终端会话，不得直接修改 React 状态、持久化文件、数据库或 PTY 进程。

## 状态与反馈

界面必须明确表达选中、悬停、焦点、禁用、运行中、失败、空状态和进行中操作。

状态反馈必须遵守：

- 正常状态尽量静默，避免重复徽标、说明行和成功色卡片。
- 异常状态说明发生了什么，以及用户是否需要采取行动。
- 破坏性操作必须说明影响范围和可恢复性。
- 进行中操作必须防止重复提交或明确处理并发结果。
- 颜色只能辅助状态，不得成为唯一信息载体。
- 浏览器预览、桌面运行时不可用和真实桌面能力必须清楚区分。

## 视觉与可访问性

工作台采用克制、低噪声、适合长期使用的桌面工具风格。

- 信息层级优先于装饰；主要工作内容必须获得最大视觉面积。
- 色彩优先服务于选中、警示、失败和运行状态，不得大面积铺设单一强调色。
- 控件密度应适合开发工作，临时编辑优先使用轻量浮层、弹出层或就地表单。
- 图标按钮必须有工具提示或等效可访问名称。
- 表单控件必须有标签；占位符不得替代标签。
- 文本、焦点和状态提示必须具备可辨识对比度。
- 不得用大面积渐变、装饰光斑或无意义插画承载核心界面。

## 关键验收不变量

- 用户进入项目后可以直接使用画布，而不是先经过营销或欢迎页面。
- 分支工作区切换会同时切换积木图、终端和 Agent 工作面。
- 终端组合不会误操作非成员或非终端对象，解散不会删除成员终端。
- 多个 Agent 控制台保持独立画布节点语义，并与普通终端积木及终端组合隔离。
- 小地图能够反映终端、折叠终端组合和 Agent 控制台的位置，但不泄露终端或 Agent 内容。
- 正常状态不重复占用视觉注意力，异常和破坏性结果能够被清楚理解。

## 维护规则

修改用户可见 UI 时必须判断本次变化属于哪一类：

1. 改变稳定产品语义或交互不变量：同步更新本文和对应行为测试。
2. 改变可演进的实现细节：更新代码与测试，不把临时样式追加为本文的永久规则。
3. 尚未确认或尚未实现的方向：记录到 [UI 路线图](ui-roadmap.md)，不得使用“必须”描述为当前能力。
4. 替换既有决策：删除或改写旧规则，不保留互相矛盾的新旧描述。

截图、参考图和一次性标注只能作为具体任务输入。除非明确标注状态、适用范围和替代关系，否则不得作为长期 UI 事实来源。
