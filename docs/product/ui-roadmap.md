# UI 路线图

## 文档地位

本文记录尚未确认、尚未实现或仍需评估的 UI 方向。

本文不是当前功能清单，也不是验收标准。本文中的条目不得使用“必须”推导为当前交付要求；只有用户确认并迁入 [UI 契约](ui.md)、代码和行为测试后，才成为稳定产品约束。

架构边界以 [架构文档](../engineering/architecture.md) 为准。积木动作扩展方向可参考 [积木动作模型](../contexts/block-graph/block-action-model.md)。

## 画布能力候选

- 自动布局。
- 框选和框选式批量操作。
- 更复杂的连线编辑。
- 多画布标签。
- 白板绘制。
- 文件节点和代码预览节点。

## Git 与工作区候选

- 删除真实 Git 分支。
- 合并、变基和冲突解决工作流。
- 更完整的工作区审计记录视图。

## 积木类型与编排候选

- Preview、HTTP 请求、测试等新积木类型。
- 与当前 Codex Agent 控制台语义不同的任务型 Agent 积木。
- 面向多种积木类型的视觉分组和工作流编排。
- 类型化动作声明和组合动作声明。
- 混合选择时只展示所有类型共同支持、且作用语义一致的动作。
- `BlockActionDescriptor` / `GroupActionDescriptor` 等声明式动作注册结构。

这些能力不得直接复用终端积木或终端组合的动作语义。进入实现前必须先确认作用对象、状态 owner、用例入口和失败恢复规则。

## 运行历史与交换候选

- 将审计记录升级为可验证的操作历史，并支持显式回放。
- 基于可逆命令或补偿动作提供撤销/重做；不能把现有 JSONL 审计直接当作撤销日志。
- 导入、导出终端工作流配置与兼容性校验。
- 恢复中断的工作流运行实例。

这些方向会改变事实来源、持久化格式或失败恢复策略，必须先建立独立领域模型和迁移方案。

## 插件与扩展候选

- Plugin 限界上下文及插件清单、安装实例和版本兼容模型。
- 插件贡献积木类型、动作、运行器或 Agent 工具的受控注册机制。
- 插件权限、签名/来源、失败隔离和卸载迁移。

当前没有 Plugin 聚合、加载器、注册中心或用户可用插件能力。进入实现前必须先确认 Plugin 与 BlockGraph、Run、Agent 的端口归属和安全边界。

## 维护规则

- 新想法先进入本文件，不直接写入 UI 契约。
- 已放弃方向直接删除，Git 历史承担历史记录，不保留失效约束。
- 已确认但未实现的方向放在“等待实现对齐”；完成后迁出。
- 路线图不得包含精确交付日期，除非项目另有计划事实来源。
