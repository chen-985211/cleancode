# UI Style Guide

## 文档地位

本文定义 cleancode 表现层共享的视觉角色、组件选择、状态呈现、动效原则和 UI 评审方法，是跨界面 UI 实现规则的事实来源。

本文不定义产品中的对象、用户能力或稳定交互结果；这些内容属于 [UI 契约](ui-contract.md)。

本文不声明尚未存在的组件库、设计工具、动效库或主题能力。当前 token、样式和组件的可执行证据仍在生产代码中；本文规定它们应如何被理解、复用和演进。

## 设计目标

cleancode 是画布优先的本地开发工作台。应用自身的 chrome 应当退后，终端、Agent、工作流关系和用户正在处理的内容应当成为视觉主体。

所有界面应保持：

- 克制：正常状态安静，颜色和动效只服务于状态、层级与反馈。
- 清晰：主要动作、当前对象、异常和下一步可被快速识别。
- 紧凑：密度适合长期开发工作，但不以拥挤换取信息量。
- 连续：对象在移动、展开、折叠、聚焦和状态变化时保持空间与身份连续。
- 可控：键盘、鼠标、触控板和终端输入不被装饰层、动画或全局快捷键抢占。
- 真实：界面只表达已经存在的能力、状态和结果，不伪造成功、运行或桌面能力。

已确认的配色取向是以中性色承载侧栏、设置选中态、拖动反馈和紧凑工具条。深色主题的画布外界面统一采用石墨灰表面、中性文字和浅灰主动作；浅色主题的画布外主动作使用石墨灰，开关开启轨道使用中灰。该范围包括侧栏、设置、收藏、任务和通知及其相关弹出表面，这些表面的 portal 入口在主题样式表中集中适配。正文文字链接在明暗主题下均保留蓝色，使用独立的 `--cc-link*`，不随主动作中性化；图标或按钮形态的外部跳转入口继续遵循所在控件的视觉规则。除下述明确调整的画布控件外，画布、画布节点及其局部菜单、终端输出、流程连线、品牌色和成功、警告、失败语义色保持各自配色。明暗主题分别按所在表面适配，不要求共用同一色值；描边、形状、文字与可访问状态共同保证识别度，不能只靠颜色区分状态。

画布内的 Agent 创建入口及其 Provider 菜单、小地图和 CleanCode MCP 开关沿用同一中性色方向，分别在自身根元素和 portal 入口覆盖主题 token，不向整个画布或节点外壳传播。Agent 入口的表面、勾选和悬停均使用灰阶；小地图的底板、导航按钮、普通缩略节点和视口框使用灰阶，并在小地图根部把选中轮廓映射到中性前景，不改变主画布的节点选中色。小地图中的运行状态、MCP 就绪与错误状态点和重连警告色继续表达既有语义。

深色主题的侧边栏使用较暗的石墨灰底板，任务面板比侧边栏更亮一档，搜索、筛选、标签与选择菜单再提亮一档，悬停和选中使用更亮的中性表面。正文使用柔和灰白，次要文字使用中灰，分隔线同步适配。配色由 `.project-sidebar-column`、`.task-surface` 与选择菜单的 portal 入口局部覆盖，任务列表、固定表头和详情正文共享同一底色。

## 实现依据

- 颜色与阴影值：`src/presentation/app-shell/styles/theme.css`。
- 全局字体、减弱动态效果和 renderer 基础样式：`src/platform/renderer-bootstrap/renderer.css`。
- 组件结构与交互：邻近生产组件及其行为测试。

本文未覆盖的表现问题，先检查同一用户流程中的相邻组件和现有语义 token；仍无法确定时再与用户确认，不凭个人偏好发明长期规则。

不得因为某个旧组件存在就机械复制。相邻组件之间存在冲突时，应确认哪一个表达了当前产品语义，并在任务范围内收敛差异。

## 视觉层级

### 表面

界面优先使用背景、画布、chrome、普通表面、浮层表面和状态表面的既有语义 token。组件不得直接使用颜色字面量，也不得把某个状态颜色挪作无关装饰。

主要角色包括：

| 角色             | 当前 token 倾向                                           | 使用边界                       |
| ---------------- | --------------------------------------------------------- | ------------------------------ |
| 应用背景         | `--cc-background`                                         | 窗口整体背景，不用于卡片强调   |
| 空间画布         | `--cc-canvas`                                             | React Flow 工作面和空间背景    |
| 应用 chrome      | `--cc-chrome*`                                            | 导航、工具条和应用外壳         |
| 内容表面         | `--cc-surface*`                                           | 节点、表单、菜单和局部容器     |
| 终端与组合表面   | `--cc-terminal-shell`                                     | 终端外壳、标题栏和组合表面     |
| 终端与组合控件   | `--cc-terminal-control*`                                  | 工具条按钮的表面、边界与前景   |
| 侧栏拖动反馈     | `--cc-sidebar-drag-*`                                     | 项目拖动表面、边界与落点指示   |
| 设置选中态       | `--cc-settings-selection-*`、`--cc-settings-navigation-*` | 设置选项与导航的中性选中材质   |
| 设置开关         | `--cc-settings-switch-*`                                  | 开启轨道、焦点与明暗主题圆点   |
| 主要动作         | `--cc-primary*`                                           | 当前流程的单一主动作           |
| 正文文字链接     | `--cc-link*`                                              | 明暗主题中的蓝色文字链接       |
| 成功、警告、失败 | `--cc-success*`、`--cc-warning*`、`--cc-danger*`          | 只表达对应语义，不作为品牌装饰 |
| 边界与焦点       | `--cc-border*`、`--cc-ring`                               | 分隔、输入边界与键盘焦点       |
| 画布节点选择     | `--cc-workbench-node-selection`                           | 终端、组合与 Agent 的选中轮廓  |
| 画布连线选择     | `--cc-workbench-edge-selection`                           | 选中流程连线                   |

同一状态必须同时具有文字、图标、形状、可访问属性或结构中的至少一种非颜色表达。正常状态不得使用大面积成功色或持续高亮。

终端节点外壳、标题栏和终端组合表面共用 `--cc-terminal-shell`，与当前主题的终端默认背景衔接；画布继续使用独立的 `--cc-canvas`。终端与组合工具条按钮统一消费 `--cc-terminal-control`、`--cc-terminal-control-border`、`--cc-terminal-control-foreground` 及其 hover、pressed、active token，由主题提供明暗适配。按钮常态背景贴近所在表面，通过清晰描边保留按钮边界；悬停、按下和激活反馈使用中性表面，不因动作具有启动语义而套用主色或成功色浅底。停止等语义色例外遵循下文状态呈现规则。具体色值以 `theme.css` 为准，不在组件中复制。

### 层级与阴影

优先通过排布、留白、边框和表面差异建立层级。阴影只用于确实离开当前平面的节点、菜单、浮层和模态界面，并复用现有 `--cc-shadow*` token。

不得通过连续嵌套卡片、多个强边框或多层重阴影制造层级。一个区域如果不是重复对象、浮层、节点或需要明确边界的工具，不应默认包成卡片。

### 字体与信息密度

应用继续使用 renderer 中定义的原生系统字体栈和当前基础字号。路径、命令、ID、端口和代码等字面内容可以使用等宽字体；产品说明和操作文案不得因为“开发工具感”而全部等宽化。

文字层级依靠字号、字重、颜色和间距共同表达。大标题只用于真实顶层页面或模态任务标题；节点头部、工具条和设置项保持紧凑。长项目名、分支名、路径、命令和翻译文本必须有明确的截断、折行或滚动策略，不得覆盖相邻控件。

## 布局与桌面壳

- 主工作内容获得最大可用面积，应用级控件不得形成无业务价值的常驻栏。
- 原生窗口按钮安全区、拖拽区和可交互控件必须分离；可点击控件不得落入窗口拖拽命中区域。
- 使用 `min-width: 0`、`min-height: 0` 和明确的内部滚动容器保护弹性布局，不让整个窗口因局部内容溢出。
- 工具条按作用域和频率分组。高频动作保持直接可见，低频动作进入更多菜单、局部浮层或设置面。
- 复杂表单默认纵向排列；只有比较关系明确或空间受限时才使用并排布局。
- 画布、终端和 Agent 正文中的滚动、文本选择和输入优先于外层画布手势。
- 设置页内容区与导航的滚动条复用 `--cc-scrollbar`，使用透明轨道、细圆角滑块和明确的悬停、拖动反馈；保留原生滚动与拖拽，内容区预留稳定滚动槽，避免展开内容时横向跳动。

## 组件选择

组件必须表达正确的交互语义，不能只因为外观接近就互换：

| 用户目标                 | 应使用                   | 不应使用                 |
| ------------------------ | ------------------------ | ------------------------ |
| 解释图标按钮             | Tooltip 或等效可访问名称 | 需要交互的复杂浮层       |
| 展示一组动作             | 菜单                     | 手写的无键盘导航列表     |
| 临时编辑少量内容         | 就地表单或轻量浮层       | 阻塞整个工作区的大模态框 |
| 要求用户完成明确决策     | 确认对话框               | 易被误关闭的普通提示     |
| 展示短暂结果             | 应用通知                 | 持久占位的状态卡         |
| 展示需要处理或复查的错误 | 对象内联状态或保留通知   | 自动消失的成功式提示     |
| 单一肯定动作             | 主要按钮                 | 多个同权重强调按钮       |
| 取消、关闭、返回         | 低强调动作               | 破坏性按钮样式           |

高频紧凑工具条优先使用图标按钮，并提供 Tooltip、`aria-label` 或等效可访问名称。主要动作、破坏性确认和无法仅靠图标理解的动作使用可见文字。

应用通知只使用一种卡片几何与表面样式：所有信息、活动、成功、警告和错误通知共享同一宽高、内边距、图标尺寸、关闭入口、不透明表面和贴边阴影，只通过语义色与图标区分类型。第一行表达对象或状态，第二行表达来源或摘要；超出单行的文字省略，但 Tooltip、`title` 或可访问名称必须保留全文。单一动作使用统一图标按钮，进入卡片最右侧固定控制轨并位于关闭按钮之前，不占用两行内容骨架；Tooltip、`title` 与可访问名称必须保留完整动作语义。Agent、工作流或其他生产者不得选择密度或复制另一套卡片样式。

彩色状态图标不叠加同色系浅底：通知、Agent 状态与审批、画布错误占位中的独立图标底块保持透明，图标继续使用语义色。带图标的提示与操作控件使用透明或中性表面，交互反馈、描边和焦点保持清晰。无图标的文字状态、流程标签、模板类型标签和粘贴提示维持各自现有样式，不因本规则调整。

设置导航的选中态保留轻微底色、文字与图标强调，以及既有侧边指示线，统一消费 `--cc-settings-navigation-*` 中性色；浅色主题使用雾灰底与石墨灰前景，深色主题使用深灰底与浅灰前景。共享移动底板和静态回退使用同一套颜色，键盘焦点使用清晰的中性轮廓。

终端设置保留“终端”总标题，以“滚动历史”和“终端搭建动效”分别作为下一级小标题，不使用外层卡片。两组选择使用紧凑的圆角轨道、带内边距的独立滑块和文字标签，不显示原生单选圆点；搭建模式说明置于轨道下方，选项仍保留各自的可访问说明。材质使用 `--cc-segment-*`，深色主题采用深灰轨道、浅色滑块与深色选中文字，浅色主题采用雾灰轨道与白色滑块。保持单选语义、可见键盘焦点和窄窗口下完整可读的标签。键盘焦点边框独立绘制在移动滑块材质上方，选中、聚焦和按下同时发生时仍只呈现一层清晰的中性边界。

设置中的 `ApplicationSettingsSwitch` 统一使用 `--cc-settings-switch-on` 开启轨道、`--cc-border-strong` 关闭轨道，浅色与深色主题均使用中性灰；键盘焦点使用 `--cc-ring` 的中性色。圆点使用独立的 `--cc-settings-switch-thumb`，浅色主题为白色，深色主题为浅灰，开启与关闭不切换圆点颜色。轨道无描边，圆点保留内边距和轻阴影；开关继续通过轨道明暗、圆点左右位置与 ARIA 状态表达值。MCP、画布设置和工作区默认值中的消费者共享该配色；画布内的 CleanCode MCP 开关通过自身局部主题映射复用相同规则。

侧边栏工作区选中态使用 `--cc-sidebar-selection*`，分别按明暗主题提供贴合侧栏背景的雾灰与石墨灰表面，以及中性前景；文字、分支图标与箭头不使用蓝色强调。选中与悬停以侧栏底色为基准，只保留小幅明度差，并用字重辅助区分。侧栏普通悬停与键盘焦点分别消费 `--cc-sidebar-hover` 和 `--cc-sidebar-focus-ring`，共享移动底板与静态回退保持相同颜色。

侧边栏工作区名称旁的 Git 分支名标签使用 `--cc-sidebar-branch-badge-*` 中性色，浅色主题采用雾灰底与石墨灰文字，深色主题采用石墨灰底与浅灰文字，并保留弱描边。标签表达分支元数据，保持辅助信息层级，不使用成功色；工作区选中、悬停或获得焦点时继续使用同一套标签颜色。

侧边栏项目拖动使用 `--cc-sidebar-drag-*` 中性色：浅色主题采用雾灰表面，深色主题采用石墨灰表面；描边与落点指示线保持清晰，蒙版、描边和落点均不使用主色蓝。拖动反馈不改变项目选择、排序提交或取消语义。

侧边栏当前项目使用中性短竖线标记，消费按明暗主题适配的 `--cc-sidebar-current-marker`；其他项目保留弱化圆点，以形状区分当前项目，不使用成功绿或主色蓝。`ProjectCurrentMarker` 在固定占位中绘制同一个圆角图形，复用共享 spring progress，以无回弹弹簧同步改变宽高与圆角，清楚呈现竖线、短胶囊与圆点之间的双向形变；主要形变阶段保持标记对比度，接近圆点后再弱化颜色。快速反向保留当前形状与速度，不得改变名称的水平对齐或延迟当前项目状态。

分支选择浮层使用 `--cc-branch-selector-*`，从浮层自身表面派生悬停与选中底色，不直接复用侧栏行的底色。明暗主题的选中底色均比浮层背景略深，选中项悬停时再加深一档，当前分支继续通过勾号表达。侧栏与分支菜单的普通文字消费 `--cc-sidebar-foreground`，深色主题中保证足够亮度，选中前景更亮，次要说明与禁用项保持各自层级。

新增跨界面组件抽象前必须证明至少有两个真实调用方共享相同语义和交互。不得为了减少 CSS 或文件数量提前建立无明确职责的通用组件。

第一方通用界面图标统一采用 Phosphor Icons（`@phosphor-icons/react`）。非画布消费者按具体图标的 CSR 路径导入，画布相关消费者进入下述 `WorkbenchIcons` 语义边界；不得重新引入 Lucide 或另一套并行的通用动作图标库。Provider 品牌图标、CleanCode MCP 标志和产品专属几何继续作为显式例外。

### 画布图标语义

主画布及其顶部工具栏、小地图、节点、节点菜单、快捷执行栏和 Agent 局部状态统一使用 `WorkbenchIcons` 提供的语义图标。消费者必须按对象、动作或状态角色选择图标，不得直接按外形从图标库另选近似实现。

| 角色                          | 规范图形                                                 | 使用边界                                           |
| ----------------------------- | -------------------------------------------------------- | -------------------------------------------------- |
| 终端、终端组合、工作流、Agent | `TerminalWindow`、`Stack`、`FlowArrow`、`Robot`          | 表达对象身份，不表达运行状态                       |
| 启动、停止                    | `Play`、`Stop`                                           | 直接执行动作，使用 `fill`                          |
| 设置、配置启动命令            | `GearSix`                                                | 打开配置，使用 `bold`                              |
| 重启、重试、重连              | `ArrowClockwise`                                         | 再次执行同一作用域动作                             |
| 刷新外部状态、恢复默认        | `ArrowsClockwise`、`ArrowCounterClockwise`               | 不得与重新执行当前作用域的动作混用                 |
| 保留会话                      | `PushPin`                                                | 默认 `bold`，已保留使用 `fill`                     |
| 编辑、确认、关闭              | `PencilSimple`、`Check`、`X`                             | X 只表达关闭或取消                                 |
| 清除已配置值                  | `Eraser`                                                 | 不得用 X 表达清除绑定或配置                        |
| 删除对象                      | `Trash`                                                  | 不得用 X 表达删除                                  |
| 断开关系、定位对象、适应画布  | `LinkBreak`、`Crosshair`、`CornersOut`                   | 定位单一对象与适应全部内容不得混用                 |
| 小地图展开、收起              | `CaretDown`，随面板进度旋转为 `CaretUp`                  | 单一方向图标跟随同一 presentation，使用 `bold`     |
| 加载、警告、错误、暂停        | `CircleNotch`、`Warning`、`WarningCircle`、`PauseCircle` | 状态必须继续由文字、结构或可访问名称提供非颜色表达 |

对象身份默认使用 `regular`，紧凑动作默认使用 `bold`，主要执行动作和明确状态使用 `fill`。同一图形的 active 状态可以通过 weight 变化表达，但不得在状态切换时更换成另一种隐喻。Provider 品牌图标、CleanCode MCP 标志、小地图几何和没有标准替代的产品专属图形属于显式例外；这些例外不得扩展成第二套通用动作图标。

终端启动入口未配置命令时表达“配置启动命令”，保存命令后表达“启动命令”，因此分别使用设置与播放图标。两者复用同一中性前景色，通过动作图形、Tooltip 和可访问名称区分，不通过蓝绿配色表达配置状态；终端组合的启动按钮同样使用中性前景色。

### 终端局部交互层

终端编辑使用锚定节点的局部浮层，按基本信息、启动命令、工作流运行方式排列。标题只保留编辑动作，不重复名称；描述使用低强调的可选多行输入，启动命令使用等宽多行编辑区并软折行；空内容与单行命令默认保留约两行高度，较长内容自动增高，不预留大块空白。输入边界复用现有 token，不叠加逐字段阴影。任务与服务使用两项分段控件并复用统一选择动效，其余配置选择继续使用 `ChoiceSelect`。

当前运行模式适用的参数直接可见，不使用逐项展开或重复参数值的摘要行。任务的成功退出码与超时并排；服务的就绪方式与超时并排，就绪文本占整行，端口参数紧接其下并采用紧凑双列。运行方式与参数间不插入独立说明段，参数组只用细分隔线区分。编辑浮层的绘制层级高于节点选中描边，描边与选中阴影不得覆盖表单。浮层默认沿编辑按钮下方展开，可超出终端节点边界；不得用终端高度截断表单或引入正文滚动条。`terminalMetadataPlacement.ts` 与 `useTerminalMetadataPlacement.ts` 负责局部避让：复用画布安全区域，优先平移到可见位置并避开触发按钮，仅在面板尺寸超过可用空间时额外缩放浮层。窗口、画布变换、内容高度和小地图等遮挡元素的几何变化后重新测量；遮挡元素由 AppShell 的 `readWorkbenchCanvasObstructions` 提供，与安全区域测量共用同一清单，BlockGraph 浮层通过表现层输入接收。位置适配与开合 spring 分层，不改变终端布局或画布 viewport，关闭时冻结位置直到退出结束。描述与命令输入随内容增高，底部的“取消”“保存”跟随内容排列，使用相同宽高、内边距和圆角，仅以颜色区分主次；窄面板中的并排参数回到单列。表单接入画布既有的 `nowheel` 与 `nopan` 隔离边界，内部滚轮和触控板捏合不触发画布缩放；表单外的画布导航能力保持可用。

终端编辑浮层的开合复用共享 surface spring，从编辑按钮附近显露并沿原路径收回。内部运行模式、就绪文本与端口条件字段的显隐由 `TerminalMetadataFieldsMotion.tsx` 拥有，以临界阻尼 spring 协调局部高度、透明度与短位移；高度测量使用未受画布缩放影响的布局尺寸，仅改变浮层内部几何，不参与终端尺寸、PTY 网格或 React Flow 测量。选择立即生效，退出内容立即 inert、禁用并退出可访问树，收敛后移除；内部字段快速反向沿当前 presentation 继续并保留当前编辑草稿。工具栏编辑按钮再次点击等同取消，打开动画可立即转为收起；退出中重新打开复用同一 live surface，但表单从已保存定义建立新草稿，不复用已取消的内容。关闭编辑立即将焦点返回编辑按钮，不等待动画；减弱动态效果时直接落位并清理退出内容。

终端搜索保持为正文右上角的紧凑局部浮层，不移动节点、不改变终端网格，也不扩展为窗口级工具栏。输入、结果计数、上一项、下一项和关闭动作使用现有表面、边框、阴影、文字与焦点 token；搜索匹配色从终端主题派生，必须同时保留当前命中与其他命中的可辨识差异。

链接失败、粘贴确认、粘贴进度与取消放在当前终端正文附近，并尽量避开主要输入和搜索区域。需要用户决策或处理的状态保持到用户操作完成，不用短暂通知替代；进行中反馈保持尺寸稳定。所有图标按钮必须有可访问名称、可见焦点和足够命中范围，不得依赖悬停才能完成键盘路径。

### 终端宿主与 Provider TUI

普通终端和 Agent terminal 的应用外框、标题、状态、错误、重试入口、xterm 默认 palette、光标与选区属于 cleancode 宿主界面，必须复用同一组语义 token 和终端主题规则。相同宿主状态不得因为 Provider 品牌不同而选择另一套边框、背景、字号或状态色；Provider 名称和能力从 descriptor 投影，不通过 Provider ID 选择专属组件或 CSS。

普通终端和 Agent terminal 必须共用同一种终端主题协调边界。wrapper 使用当前应用主题背景并承载上、左、下阅读留白；源主题 dataset 和 terminal token 作用于内层 viewport，跨明暗主题的 mismatch filter 只作用于该 viewport 及其 xterm 内容。滤镜不得作用于 wrapper 留白、节点边框、标题或第一方覆盖层。内层内容转换后的背景必须与 wrapper 当前主题背景形成同一视觉平面；右侧继续保持零留白，使 viewport 与滚动条贴住内容外框。

Agent 头部左侧使用 Provider descriptor 提供的图标和稳定 Agent 名称表达身份，不常驻重复显示 Provider 名称；Provider 名称仍须通过 Tooltip、`title`、可访问名称或等效语义可获得。图标由同一个 Provider-neutral 组件渲染 descriptor 中经过校验的矢量数据，不按 Provider ID 选择组件或 CSS，也不叠加活动圆点、角标或其他状态装饰。CleanCode MCP 控件占据头部的几何中心，左右区域使用对称布局承载身份和更多菜单；两侧内容宽度不同、名称截断或菜单状态变化时都不得带偏中心控件。

CleanCode MCP 能力开关复用设置开关的轨道与圆点材质：开启轨道使用 `--cc-settings-switch-on`，关闭轨道使用 `--cc-border-strong`，两态圆点均使用 `--cc-settings-switch-thumb`。深色主题为中灰轨道配浅灰圆点，浅色主题为灰色轨道配白色圆点；轨道无描边，圆点保留内边距和轻阴影，通过轨道明暗与圆点左右位置表达开关值。节点头部保留紧凑尺寸，悬停与键盘焦点继续使用局部中性色。ARIA 状态、旁侧运行状态点与重连入口保持既有语义，开启填色只表示能力偏好，不表示 MCP 已连接就绪。

CleanCode MCP 能力说明 Tooltip 围绕开关居中定位，内部状态标题与正文按阅读方向起点对齐，换行后共用同一左边缘。无状态或开关关闭时不保留标题占位；状态标题继承 Tooltip 自身的前景色，不消费页面前景色，避免标题不可见却留下空白。提示完整文案和既有浮层表面配色保持各自现有规则。

终端网格内由外部 CLI 写入的 ANSI、真彩色品牌色、文本布局和 TUI 控件属于运行时内容，不是第一方 UI token。应用可以在不重建会话、不改写 buffer 的前提下对整个终端 surface 做统一可读性适配，但不得逐 Provider 猜测或重写其语义色，也不得用修改用户全局 CLI 主题的方式追求截图像素一致。评审时应分别检查宿主 chrome 是否一致、CLI 内容是否可读，不能把不同 CLI 自身的视觉差异误判为第一方组件不统一。

Agent terminal 首次测量和 attach 进行中使用中性、尺寸稳定的反馈；attach 失败使用保留的警告与明确重试动作，不以空白 surface、无限 spinner 或 Provider 安装提示替代。替代 attach 失败时，既有 terminal 内容和输入能力保持原位；在途期间禁用会触发冲突重配的控件，但不添加遮挡 terminal 正文的状态层。

终端组合内每条流程使用固定左侧起点与顶边对齐的槽位。终端展开向右、向下生长，曲线依赖跟随两端当前侧边中心；不得因某节点变高而把紧凑邻居垂直居中，或横移其他流程。创建与恢复时先修复旧成员错位再呈现，不能等待第一次展开才排版。连续展开不同节点时，位置与宽高使用同一世界坐标矩形 spring 接续，不能把尚未完成的尺寸动画降为纯位移动画。

## 状态呈现

每个交互组件都必须检查适用的空闲、悬停、焦点、按下、选中、禁用、进行中、成功、失败和空状态。状态不适用时无需伪造占位。

反馈遵循以下规则：

- 进行中文案、图标或状态区域保持控件尺寸稳定，不得造成布局跳动。
- 正常和短暂成功状态保持安静。需要用户重试、复制或理解的错误保留在对象附近或持久通知中。
- 取消、关闭和返回不使用破坏性色。
- 删除、移除、解散和清除等维护控件复用所在表面的中性按钮状态，不叠加“浅红或半透明红底 + 红色图标、文字”的悬停或焦点效果。项目移除的局部确认按钮也使用中性表面与清晰边界；动作含义由图标、文案和既有确认流程表达。终端头部及通知中的“停止本次运行”保留红色停止图标，悬停与按下使用中性背景和描边；实心红色确认按钮和错误、失败反馈继续遵循各自的语义。
- 所有画布节点菜单均复用同一菜单表面、连续行列表、图标规格与交互状态，不得按节点类型插入私有分隔线；收藏、添加到快捷执行栏、重命名和任何节点类型的“移除”均使用同一前景色与悬停背景，不使用 `--cc-danger*` 或调用方私有视觉变体。完整作用域由菜单文案与画布临时高亮共同表达。`CanvasNodeMenu` 统一拥有紧凑尺寸，画布右键菜单、终端、组合与 Agent 的“更多”菜单共用同一规格：宽度 `260px`、行高 `32px`、字号 `13px`、外圆角 `12px`，减少对终端正文的遮挡。长文案单行截断，Tooltip 与可访问名称保留完整含义，定位继续避让窗口边缘。
- 画布节点（终端、组合与 Agent）的左键正式选择与右键临时选择统一使用 `2px` 实线边界、透明正文和既有节点阴影规则，由 `--cc-workbench-node-selection` 按主题提供颜色：深色模式使用 Cloud 灰（`#ADB5BD`），浅色模式保留既有低饱和蓝灰色。流程连线使用独立的 `--cc-workbench-edge-selection`，分别保留浅色模式的低饱和蓝灰色和深色模式的浅蓝色较粗实线；节点与连线不得共用选中色 token，调整连线强调时不得覆盖节点选中态，也不得将深色节点配色应用到浅色模式。两者均与主要动作色分离；同类对象不得使用虚线、正文色层或右键专属光环制造第二套选中语言，功能差异由菜单和选择生命周期表达。
- 快捷执行栏嵌入底部状态栏右侧，以微型 Dock 呈现绑定，父容器只排列，不增加整体表面、外框或左侧分割线。紧凑入口使用透明底色，常驻展示低强调编号与类型图标，完整名称、类型和快捷键由共享 Tooltip 呈现；悬停或键盘焦点时仅图标轻微上浮放大并显露淡表面，编号和点击区域保持原位。动效使用既有语义 token，减少动态效果时取消图标位移与缩放。添加入口与按需展开的空位更安静，不使用纯白连续卡片、粗边框或强阴影；不显示运行按钮、执行装饰、专属运行状态或悬停操作菜单。快捷管理的完成按钮、排序落点、键盘焦点框和临时清除投放区统一使用既有中性色 token，不使用蓝色强调；清除素材保持灰阶，交互反馈通过表面明暗和清晰边界表达。无效绑定除警告色外还必须保留可见文字状态。窄窗口优先截断状态栏路径，固定编号、顺序和入口命中区域保持稳定。
- 快捷位内部排序由 `useQuickExecutionPointerDrag` 接管指针输入。底部只排列已绑定入口，不为隐藏空位预留宽度；普通起拖和外部对象拖入都不展开空位。添加与整理浮层共用不透明菜单表面、细边框和紧凑标题。添加列表以图标、名称和次要类型信息分层，长名称单行截断并保留完整 Tooltip。整理使用状态栏上方的五行列表，固定编号以低强调键帽呈现，绑定行显示名称、类型和拖动把手，空位使用文字占位，不画大尺寸空卡片；标题与轻量完成控件位于面板内，列表在高度不足时内部滚动，底部入口保持原位。底部 Dock 的拖影保持紧凑图标尺寸，不展开名称或显示编号；整理面板不使用图标上浮放大或邻近清除区颤抖，以完整行拖动编号、图标、名称、类型和把手，尺寸与抓取位置保持不变，松手后以落位编号交接。不可用绑定沿用警告边界。保持抓取位置直接跟随指针，不套缓动。交换预览只移动目标绑定的视觉内容，编号与命中区域不动，松手沿回位曲线收敛至对应位置的静止图标几何，交换、移入空位和取消都使用当前静止布局作为终点，不使用起拖前悬停上浮的坐标。保留既有弹簧响应与完整的自然减速收敛，不为提前结束而压缩回位节奏；接近落点时淡出拖影表面，图标连续交接。回位期间保持预览复原过渡，结束后等待新的指针移动或键盘焦点再恢复悬停上浮，避免连续二次跳动。对象拖入整条快捷栏和快捷位排序的命中区域使用静态边界或背景反馈，不移动栏本身、不遮盖名称，也不播放持续动画；`prefers-reduced-motion` 下取消非必要过渡。候选与整理浮层必须支持可见焦点、Escape 和外部点击关闭，新增不得再出现位置选择浮层。

远程目录、Git、Agent CLI 和 PTY 操作可能具有额外延迟。等待期间应保持稳定的进行中呈现，不得用高频闪烁或不断重排掩盖延迟。

## 动效

### 原则

动效只服务于输入反馈、状态变化、空间关系和结果确认：

- 直接操控：拖动、缩放、调整大小和画布移动跟随输入，不额外播放脱离输入的动画。
- 空间连续：菜单从触发点附近出现，展开与收起、进入与返回使用一致的空间关系。
- 可打断：新输入可以接管、取消或重新定向尚未完成的动画。
- 速度连续：手势结束后的运动尽量承接当前方向和速度，不先停顿再重新启动。
- 物理克制：生产力工具优先快速收敛、低弹性或无弹性运动，不使用持续弹跳制造“活泼感”。
- 状态驱动：动画由当前状态和目标值驱动，不以固定等待承担业务完成条件或焦点同步。
- 性能优先：动画不得阻塞终端输入、画布拖动、滚动、PTY 输出或应用层事件投影。

### 当前节奏

CSS 动效通过 `theme.css` 的语义 token 选择节奏与曲线；调用方按交互含义复用，不得在普通 `transition` 或 `animation` 中重新写近似时长和 bezier。JavaScript 弹簧继续使用各 owner 的 response 与阻尼配置：

| 级别     | 当前参数或范围                                    | 适用场景                                 |
| -------- | ------------------------------------------------- | ---------------------------------------- |
| 按压反馈 | `--cc-motion-duration-press: 100ms`               | 按压、即时位移和最短局部反馈             |
| 状态反馈 | `--cc-motion-duration-feedback: 150ms`            | 悬停、焦点、颜色、边框和小范围状态变化   |
| 表面过渡 | `--cc-motion-duration-surface: 180ms`             | 菜单、浮层和局部展开收起                 |
| 品牌显露 | 延迟 `280ms`，持续 `700ms`；后续显露循环 `2300ms` | 初始空画布的字标显露与低频彩色 band 显露 |
| 空间定位 | response 约 `0.30–0.42s`                          | 画布聚焦、适应视图和与距离相关的空间移动 |
| 编排演出 | 约 `300–9100ms`                                   | 已提交的多对象工作流逐步或按层搭建与收束 |
| 持续运动 | 品牌扫光与 spinner 均使用独立语义 token           | 只用于空画布字标或确实持续进行的状态     |

精确时长和 spring response 不是产品语义。逐步搭建允许为解释对象与依赖的先后关系采用更长的整体时间，但相邻步骤仍应快速收敛，大图必须压缩步骤间隔并设置有限的启动窗口，不能让演出时间随节点数无限增长。

桌面端恢复完成且没有项目时，画布直接呈现无卡片边界的 `CleanCode` 品牌和打开项目主操作，不叠加欢迎面板、说明或装饰图标。打开项目使用中性浅色表面、细边框和前景色，不使用主色实心填充。品牌在该空状态首次挂载时播放一次从紧缩字距到最终字距的透明度显露；挂载后先保留一段短暂视线落位时间，再以明显可辨但不拖沓的节奏展开。显露完成并短暂静置后，一条有限宽度的彩色 band 可以按 `DiaTextReveal` 语义低频循环：色带前方保持透明，经过后的文字立即沉降为前景色，每轮使用约 `1.5s` 完成显露，并在完整字标上停顿约 `0.8s`；循环不得改变字标几何、按钮稳定性或可访问名称。加载、恢复失败和浏览器预览继续使用各自的状态表面，不复用品牌演出。`prefers-reduced-motion` 下取消等待、字距显露和持续显露循环，直接显示最终字距与前景色。

锚定菜单、Popover 与状态面板的 presence 由 `src/presentation/shared/components/SurfaceMotion.tsx` 和 `src/presentation/shared/motion/surfacePresence.ts` 统一拥有；模态抽屉、全屏设置与 Dialog 复用同一状态机及 `src/presentation/shared/motion/surfaceIsolation.ts` 的隔离租约。状态统一为 `closed → opening → open → closing → closed`：关闭意图发生时 surface 立即 `inert`、从可访问树隐藏并停止接收指针，退出收敛后才释放 DOM；模态背景隔离租约跟随可交互的 open 意图，关闭一开始即释放该 surface 的租约，让新输入可以接管，仍处于打开状态的其他模态租约继续保持隔离；退出中反向打开必须复用同一 live surface。锚定表面从触发点方向短距离进入，Tooltip 使用更轻、更短的同类语义；小地图继续复用该 presence 生命周期，但由 `src/presentation/app-shell/workbench/minimap/minimapPanelMotion.ts` 以一条临界阻尼 spring 同步投影面板高度、透明度和方向箭头，底部控制行固定在画布右下角并避开状态栏，面板向上展开、向下收起，快速反向从当前 presentation 接管，小地图内的视口平移仍保持直接操控；Drawer 从所属边缘进入，Dialog 的背景与内容同步，Notification 保留逻辑项与 live presentation 项以支持进入、内容更新和退出。嵌套模态 surface 必须引用计数背景隔离，关闭其中一个不得提前恢复底层交互。画布菜单继续使用下文更严格的 coordinator，不并入通用 surface owner。

任务列表与详情通过共享 surface owner 的 `page-right` 预设同步投影进退位置和透明度，页面保持原尺寸，不使用短 CSS keyframe 代替退出 spring。详情导航、标题与任务栏采用一致的左侧边界，正文单独限制阅读宽度；返回、编号和状态保持为紧凑导航行。

锚定 surface 通过 `useOutsidePointerDismiss.ts` 统一接管外部 `pointerdown` 的关闭时序，不得在各组件的 document 冒泡监听器中自行关闭。关闭必须在捕获阶段同步提交，使 surface 在底层画布或控件处理同一次输入前已经进入 `closing` 与 `inert`。调用方必须显式选择输入所有权：画布上的临时菜单、选择器、状态面板和就地表单使用 consume 策略，接管该次指针及其兼容事件直到序列结束，不能把同一次按下、抬起或点击泄漏给 React Flow；只有产品明确要求一次手势同时激活外部目标时才使用 passthrough。拥有可见层级边界的菜单或模态 surface 仍可使用专用 dismiss layer 或 coordinator。输入所有权不改变退出 spring、DOM 保留或快速反向规则。

项目内自定义下拉选择菜单统一以默认 Agent 选择器为视觉和运动基准，覆盖工作区项目、任务项目与标签、语言、默认 Agent、工作区默认内容的 Agent/模板添加器、外部打开选项和终端高级配置选择框：`directionalMenuMotion.ts` 统一拥有约七成初始尺度、透明度提前显露和无回弹临界阻尼曲线，向上菜单只镜像垂直来源；箭头只表达固定打开方向，不因开关状态旋转。`menuOptionHighlightMotion.ts` 与 `useMenuOptionHighlightMotion.ts` 统一拥有鼠标悬停和键盘焦点共用的单一移动高亮；存在当前值的紧凑选择菜单以 Agent 的 check 与 ARIA 状态表达选中，不增加常驻选中底色。鼠标点击触发器打开任一上述选择菜单时，焦点落在菜单容器，不得通过自动聚焦当前值制造默认灰底；指针移入可用选项后才出现悬停高亮；移出且没有选项焦点时取消，失焦后不得残留高亮。方向键导航提供可见焦点并跳过禁用项，聚焦滚动区外的选项时将其滚入可见区域；分组、菜单上翻和减少动态效果不得改变该语义。纯动作菜单不得虚构选中态，文字和图标不参与位移或弹跳。`ChoiceSelect` 打开期间跟随触发器及其祖先的样式、类名和尺寸变化重新定位，包括画布与编辑浮层的 transform；重定位不重置菜单焦点或提交选中值，关闭或卸载时释放观察器和待执行帧。同类选择框消费 `ChoiceSelect`；需要项目路径、分组或动作行等专属内容的菜单复用 `choiceMenuNavigation.ts` 与共享高亮规则，不复制键盘策略。上述菜单消费 directional surface owner；默认 Agent 选择器保留既有 canvas presence/input owner，只作为参数基准并消费共享选项高亮。这些选择菜单共用同一中性 hover token；`prefers-reduced-motion` 下直接投影端点。分支切换的搜索式 Popover 是下拉选择器的明确例外，保留原有搜索、焦点和选中呈现。其他下拉选择框（包括此前使用原生 `select` 的终端配置）必须接入这套自定义交互。小地图、项目卡片等非选择 disclosure 与画布上下文动作菜单不因外观相似被转换成选择器。

同一 Notification 的运行状态更新由 `notificationStatusMotion.ts` 保留旧状态视觉层并交接到最新状态；spinner 与结果图标的短位移、缩放和透明度由临界阻尼 spring 同步投影，标题与颜色只做短交叉淡化，不能让文字产生装饰性回弹。图标 spring 收敛后才释放旧视觉层；只有最新层保留在可访问树，连续更新继续追加最新事实并让在途层从当前 presentation 退出。可导航消息把图标和两行内容放进一个真实、透明的正文按钮，最右侧动作与关闭按钮仍是外层卡片的兄弟控件；不得在 section 上伪造 button role、形成嵌套按钮或增加第二层常驻底板。正文 hover 只使用轻微表面色，focus-visible 使用不改变几何的内嵌焦点环，active 不缩放卡片或内容。`prefers-reduced-motion` 下直接投影最新状态，停止 spinner，但进行中语义继续由静态图标、文字和可访问状态表达。

应用右上角的收藏、语言、主题和设置入口属于同一组 utility button；按下必须在当前帧提供共同的短位移与缩放反馈，松开后由无回弹的临界阻尼 spring 从当前 presentation 恢复。触发后的 surface 同样必须表达来源：收藏与主题 Drawer 从所属右侧边缘进入并沿原路径退出，设置全屏表面从右侧短距离进入并退回，语言菜单从按钮的右下锚点生长并缩回。surface 的位移、缩放和透明度由同一条可反向的临界阻尼 spring 协调，不能在 JavaScript presentation 外再叠加 CSS transform transition。鼠标、触控笔与键盘激活必须复用同一反馈，非主按钮不得触发按压态；`prefers-reduced-motion` 下仍保留即时状态反馈，但直接投影静止端点。

设置页的固定标题与左侧导航不参与分类切换；内容按 `快捷键 → 画布 → 工作区 → 终端 → Agent → 问题反馈` 的导航顺序建立空间关系，向后选择时新内容从右侧进入、旧内容向左退出，反向选择时镜像路径。新旧内容使用独立的 X 与透明度临界阻尼 spring；连续切换必须保留每一层当前 presentation，并只继承朝向新目标的速度。退出层立即 `inert` 且从可访问树隐藏，收敛后释放；`prefers-reduced-motion` 下直接投影当前分类并清理退出层。

按钮组、分段控件、选项卡和开关的选择反馈由 `selectionMotion.ts` 与 `useSelectionMotion.ts` 统一拥有。语义选中状态和对应内容必须在输入提交后立即更新，motion 只拥有选中材质的临时 presentation，不得延迟业务状态。连续、相邻且等尺寸的选项复用一个真实选中材质，从当前 X/Y presentation 与速度收敛到目标；设置分类导航、收藏范围分段选择和 Agent 权限分段属于该形态。彼此分离的卡片不得让高亮材质跨越空白飞行，主题卡片、开关、快捷键录制态和 Agent Provider 状态等消费者应以同一条无回弹临界阻尼 spring 在各自边界内投影描边、位移、轻微尺度或显露进度。延迟挂载或尚无有效几何时必须保留语义选中项的完整静态材质，不能出现只有文字颜色、没有选中底板的中间态；几何就绪后再无缝交给共享 spring。快速连续选择从当前 presentation 重定向，不重播、不排队；文字和图标只做状态颜色反馈，不参与装饰性弹跳。`prefers-reduced-motion` 下直接投影同一最终选择状态。

终端设置的弹性分段控件是显式的手势型例外，由根级表现层 `ElasticSegmentedControl`、`elasticSegmentMotion.ts` 与 `elasticSegmentGeometry.ts` 统一拥有，使用 Motion 的 motion value 与 spring，不复用普通选择底板的平移控制器。点击包含拉伸和收拢，拖动保留抓取偏移，松手使用近期指针速度预测落点并承接速度；边界提供渐进阻力与压缩。任何阶段均可由新输入接管，不排队或跳回旧端点。拖动只预览，释放后提交一次；取消、捕获丢失及外部值更新清除旧手势，迟到回调不能覆盖新状态。动画只改变材质，文字和轨道不随之伸缩。系统减弱动态效果继续由共享偏好 owner 提供，保留选择结果，取消弹性和惯性演出。两个设置消费者只提供选项和值，不各自定义物理规则。

新建分支工作区表单复用统一 surface presence，以所属项目的 “+” 按钮为固定来源，在按钮下方通过临界阻尼 spring 协调短位移、缩放和透明度，关闭时从当前 presentation 沿原路径收回；按钮必须通过 `aria-controls` 和 `aria-expanded` 表达控制关系。关闭意图发生后表单立即停止交互，spring 收敛后再清理草稿和释放 DOM；快速反向复用同一 live surface。Escape 或外部关闭手势都把焦点返回触发按钮；用于关闭表单的第一次画布手势只负责关闭，不得同时触发画布选择、平移或放置。

通用弹簧解析数学、有限子步和收敛判断由 `src/presentation/shared/motion/motionSpring.ts` 维护，同时支持临界阻尼与欠阻尼；utility button、分支表单、通知图标与 surface 进出复用 `src/presentation/shared/motion/springProgressMotion.ts` 的逐帧生命周期和重定向，设置分类的多层重定向由 `src/presentation/app-shell/app-features/settings/applicationSettingsPaneMotion.ts` 负责，具体空间投影仍由各 owner 决定。各相机、菜单和组合反馈 owner 继续决定 response、阻尼、阈值及速度重定向策略。公共层消费完整经过时间，不能用截断单帧 delta 的方式丢失后台或延迟帧时间；参数值只有在本身是算法边界时才属于测试契约。

工作区默认内容设置采用 Agent、模板两个同级小节和紧凑分隔行，不使用包围整页的大卡片或嵌套勾选表单。Provider 使用注册贡献中的图标；模板来源通过图标和文字表达。添加器复用锚定 surface spring 和键盘导航，外部点击通过共享 outside-pointer owner 在捕获阶段关闭，并允许同一次手势激活其他设置控件。已添加行的局部高度、透明度与短位移由 `WorkspaceDefaultsMotion.tsx` 命名 owner 使用临界阻尼 spring 协调，让相邻内容随添加与移除自然让位；只改变该设置列表局部几何，不参与主画布、React Flow 或 xterm 测量。快速移除后重新添加复用仍在退出的同一行，从当前 presentation 重定向；退出行立即 inert，焦点返回所属添加按钮。增减、添加和移除按钮复用 utility button 的即时按压和 spring 恢复；自动运行开关复用统一 selection motion。减少动态效果时直接呈现最终状态并清理退出行。

CleanCode MCP 工具分类的局部开合由 `AgentMcpToolCategory.tsx` 拥有，复用共享临界阻尼 spring，同步投影列表高度、透明度、短位移和箭头角度；相邻分类随局部高度自然让位。连续开合从当前 presentation 重定向，不能跳回端点或排队；关闭立即 inert 并退出可访问树，收敛后隐藏正文。列表换行或窗口尺寸变化时更新内容测量，展开完成后恢复自然高度；减弱动态效果下直接投影同一端点并清理 RAF。默认折叠和分类开关的产品语义仍由 UI 契约拥有。

普通布局属性不得仅为“看起来平滑”而持续补间。需要空间连续性的局部 disclosure 可以使用受控的 grid 轨道过渡；涉及主工作台、xterm 或 React Flow 测量的网格变化必须作为命名 owner 例外审查，优先让视觉表面使用 `transform` 与 `opacity`，并验证动画期间输入、resize 和测量稳定。

主侧栏由 `projectSidebarMotion.ts` 命名 owner 协调：展开和收起的运动期间，应用网格与全尺寸画布外壳保持稳定，标题栏 chrome 与侧栏正文两个实心视觉表面以固定几何共享同一份位移 presentation，沿所属边缘作为一个整体进出；折叠按钮留在窗口安全区，不跟随视觉表面离场，标题栏导航在收起状态仍保留固定流内高度，不能让正文产生垂直位移。同一个无回弹的临界阻尼 spring 通过合成器 `transform` 同步投影上述两个侧栏表面、画布空间层和居中画布控件，其中空间层让出完整侧栏宽度，居中控件移动一半宽度。状态栏是同一 owner 管理的局部布局例外：两侧固定窗口留白，只按当前侧栏占用更新左侧 margin，由绝对定位边界自然收放宽度；外框、玻璃材质、路径和快捷栏共享同一实际边界，右边框与右侧控件在展开、收起、快速反向和减弱动态效果下都保持在窗口内。该布局变化只影响独立状态栏，不参与画布、React Flow 或 xterm 的尺寸测量。逐帧 presentation 不得改写网格轨道、画布尺寸、React 状态或继承型 CSS 变量；只有 spring 到达展开端点时才一次性提交扣除侧栏后的真实可见画布边界，关闭开始时可以一次性恢复全宽，因为新增区域仍在应用裁剪边界之外。端点提交后必须移除这些大面积 transform，让 React Flow 与 xterm 回到普通像素投影；画布外壳使用不可编程滚动的裁剪方式，不能让焦点或 `scrollIntoView` 把隐藏溢出的 motion surface 滚进侧栏区域。逻辑可用宽度只在侧栏意图端点变化时更新，创建与聚焦继续以画布裁剪后的当前可见矩形为准。侧栏视觉表面与空间让位进度都必须限制在合法端点内，不能让正文在到位后反向摆动。关闭意图发生后侧栏立即退出可访问树并停止接收指针，但视觉表面只在空间运动结束后隐藏；快速反向必须从当前 presentation 与速度继续，不重置 padding、内容排版、React Flow、xterm 或 Agent surface。`prefers-reduced-motion` 下取消大范围滑动并直接投影相同端点。spring response、阻尼和收敛阈值属于 owner 的实现细节，不构成产品契约。

项目卡片排序由 `useProjectSidebarReorder.ts` 接管输入，并由 `projectReorderMotion.ts` 统一拥有位移 presentation。被抓住的卡片必须逐像素跟随指针，滚动发生时也保持同一抓取点；其他卡片按被拖对象的实际外高让位并使用无回弹的临界阻尼 spring。松手后在持久化结果未返回前保留当前 presentation；权威顺序到达时使用 FLIP 从当前屏幕位置收敛到新布局，失败、Escape 或失焦则从当前位置返回原布局。该层不得预测或写回项目顺序；`prefers-reduced-motion` 下保留直接拖动并即时投影让位和最终端点。

画布空白菜单、对象菜单、终端/组合/Agent 更多菜单和默认 Provider 菜单的进出场由 `src/presentation/app-shell/workbench/menus/canvasMenuMotion.ts` 与 `CanvasMenuMotionProvider.tsx` 统一拥有。菜单表面从实际触发点或控件锚点以约七成的紧凑初始尺寸开始，沿透明度、显著缩放和短位移逐帧生长，约 100ms 时仍应处于可辨识的生长中段；收起使用同一 presentation 和空间关系反向缩回，不能以接近完整尺寸的短淡入淡出冒充生长。菜单是非模态浮层，画布不得随菜单 presentation 淡化、着色或模糊；一个没有视觉样式的 dismiss layer 只在菜单可交互期间接管菜单外指针。主按钮按下必须由该层捕获并关闭菜单，完整指针序列不得泄漏给 React Flow 平移或底层控件；次按钮按下由统一 coordinator 同步关闭当前意图并保留一次性输入遮罩，紧随其后的 `contextmenu` 只负责阻止原生菜单并释放遮罩，不得再次切换。该遮罩必须有超时自清理，第二次右击无论落在输入接管层还是仍在进场的菜单表面都执行同一输入路径。非即时运动使用 `requestAnimationFrame` 驱动的临界阻尼 spring；新开、关闭、Escape、外部点击或另一菜单接管时，统一 owner 必须保留当前 presentation，并且只继承朝向新目标的速度；背离新目标的旧速度必须在重新定向时归零，使下一帧立即响应新意图，不得排队播放、重置到端点、复制第二个可交互 surface 或依赖 CSS `animation` 完成事件。关闭中的 surface 只为视觉连续性保留，必须立即 `inert`、从可访问树隐藏并停止接收指针，收敛后才释放 DOM；同一菜单反向打开必须复用该 live surface。菜单协调器同时只允许一个可交互菜单，工作区切换会清空全部在途状态。`prefers-reduced-motion` 下直接投影同一最终状态，菜单作用域、透明输入接管层、互斥、焦点和退出清理语义保持不变。spring response、收敛阈值和最长兜底时间属于统一 owner 的实现细节，不构成产品契约。

程序化画布相机运动由 `src/presentation/app-shell/workbench/viewport/workbenchViewportMotion.ts` 统一拥有。调用方必须通过 `instant`、`quick`、`spatial` 或 `adaptive-focus` intent 表达运动原因，不得直接调用 React Flow 的 viewport helper，也不得在消费者中维护裸时长、spring 参数或独立取消策略。正在运动时派生新锚点必须读取该 owner 的当前 presentation，不能从可能滞后的 React Flow viewport 重新计算；连续节点聚焦的可读性与尺寸适配必须以该 owner 尚未完成的目标倍率为基准，不能把 flight 临时缩小的 presentation 倍率作为下次最终目标。目标倍率必须保留到最终 viewport 应用完成，取消、失败或完成后恢复读取当前实际倍率，消费者不得另存倍率缓存；相同语义和目标的连续 overview 请求必须由调用协调器合并，目标已经呈现时直接 no-op。`instant` 用于持久化 viewport 恢复和直接操控预览；`quick` 用于用户主动触发的 zoom 与适应画布；`spatial` 用于创建显露和对象集合定位；`adaptive-focus` 同时按当前 viewport、目标屏幕距离和 zoom 级差调整收敛速度。intent 的精确参数仍是实现细节，不构成产品契约。

常规节点定位通过 `workbenchNavigationFocus.ts` 复用方向导航的可读缩放、尺寸适配与 `adaptive-focus` 默认意图，显式传入的定位意图与倍率仍由调用方负责。快捷位和审批卡片的对象集合定位共用该模块的安全区域适配，保留完整可见目标并继承尚未完成的目标倍率。消费者只确定目标对象与选择、输入结果；新建显露、整理后的全景、空白返回和直接操纵小地图继续遵守各自的明确意图。

滚轮与触控板 wheel 缩放由 `src/presentation/app-shell/workbench/viewport/workbenchDirectZoom.ts` 统一拥有，输入接管位于 `src/presentation/app-shell/workbench/viewport/useWorkbenchDirectZoom.ts`。React Flow 的原生滚轮缩放保持关闭；输入按 wheel delta 模式规范化后在 `log2(zoom)` 上连续累积，同一显示帧内的事件只合并一次。一个 wheel burst 使用同一条快速、无回弹的临界阻尼曲线：新输入只从当前 presentation 重定向累计目标并继承当前 zoom 速度，不得为每个 wheel delta 分别排队播放动画，也不得通过首帧硬跳、距离截断或固定分段补间制造接缝。连续帧链已经排定时，后续 wheel 事件只能更新目标和 burst 结束时间，不得重置上一 presentation frame 的积分时钟；一帧前到达的高频事件必须作为同一批输入推进。不同刷新率在相同经过时间必须得到相同 presentation。每批输入必须从当前 presentation 计算指针下的世界坐标，并在各帧 viewport 中保持该锚点不漂移。一个 wheel burst 只在输入停止且曲线收敛后提交一次最终 viewport；程序化相机、画布平移或恢复输入会取消未完成的直接缩放，反向接管亦然。`nowheel` 内容继续优先接收自己的滚动，原生触摸 pinch 不受 wheel 接管影响；`prefers-reduced-motion` 下每次输入即时呈现，但仍等 burst 结束后统一提交。response 和收敛阈值是统一 owner 的实现细节，不构成产品契约。

画布普通单选与空白返回的相机目标由 `src/presentation/app-shell/workbench/viewport/useCanvasSelectionViewport.ts` 统一协调，并继续交给上述相机 owner 执行。标题普通单选复用现有节点中心与可读缩放算法，默认可读倍率为 `100%`；空白返回捕获清除前的唯一整体选择，以同一节点中心为锚点精确回到 `50%`，不得重新计算全部内容的外接范围中心。没有唯一选择或锚点不可用时，以当前 viewport 中心缩放，不能从组合候选或其他临时多项选择中任取节点。平移和缩放必须作为同一个 `adaptive-focus` 目标连续收敛，不能先缩放再平移或先停顿再启动第二段动画。新的选择、平移、缩放或其他定位输入必须从当前 presentation 重新定向；`prefers-reduced-motion` 下即时应用同一最终中心和缩放。组合候选以及已经自行负责相机的快捷键和小地图入口不得叠加第二次选择聚焦。

非即时程序化相机运动使用 `requestAnimationFrame` 驱动的临界阻尼 spring，阻尼比固定为 `1`，不产生装饰性回弹。当前 motion token 的 response 为：`quick` 约 `0.30s`、`spatial` 约 `0.34s`、`adaptive-focus` 约 `0.34–0.42s`；response 描述弹簧响应快慢，不是固定动画时长。统一 owner 必须在世界坐标相机中心与 `log2(zoom)` 上保存位置和速度，再逐帧投影为 React Flow viewport；不得以 viewport transform 的 X、Y 差值估算空间移动，否则锚定缩放会随节点绝对位置改变曲线。纯锚定缩放的空间移动距离为零，双向缩放在对数尺度保持同一节奏，只有相机中心真实跨越画布时才允许 flight。新目标必须从当前呈现值重新定向并继承速度。用户开始拖动、工作区恢复或更新的定位意图会立即取消旧运动，迟到完成不得重新激活旧目标。曲线、阈值和取消语义只能在统一 owner 中调整，并必须由距离、缩放、锚点漂移、缩放单调性、重新定向、异步完成和 reduced-motion 参数矩阵覆盖。

依赖相机位置的同屏反馈必须与成功应用的 presentation frame 使用同一事实源。小地图 viewport 框与缩放百分比通过相机 owner 的轻量实时信号逐帧跟随，订阅和重渲染范围分别只覆盖框本身与百分比 `<output>`；不得为同步反馈而把程序化中间帧写回 `WorkbenchCanvas` React 状态、重渲染小地图节点或持久化 viewport。最终 viewport 仍只在有效运动完成时提交一次。

画布空间对象的创建、组合展开收起和缩放细节层级由 `src/presentation/app-shell/projections/workbenchObjectMotion.ts` 统一拥有，逐帧 presentation 由 `src/presentation/app-shell/workbench/nodes/workbenchObjectSpring.ts` 执行。新 Terminal 或 Agent 必须先以最终节点几何进入画布，再让完整视觉外壳从自身中心等比显露；删除沿同一路径缩回中心，创建与删除都不得逐帧改变 React Flow、xterm 网格或 resize 的布局几何。组合拖放的专用表面反馈属于下文明确的独立 owner，不得被创建动效规则误判为禁止。创建后的程序化相机聚焦至少让对象先呈现一帧，并继续遵守统一相机 owner 的取消与最终焦点契约。

MCP 搭建编排只能决定对象何时出现、从哪里开始、终端顺序以及连线何时显露，不得拥有另一套终端、组合或连线材质动效。编排在对应阶段只投影通用的 pending/entering 意图；Terminal、Terminal Group 和工作流 Edge 各自通过上述画布对象原子 owner 解释该意图，因此手动创建与 MCP 创建必须复用同一种出现效果。编排的阶段信号是一次性触发器，不得在 React 重投影后重复播放创建动效。

组合展开时，成员从折叠组合中心回到持久化位置；收起时沿同一路径整体缩回中心。成员位移与尺度使用同一 spring 进度，保留相对间距，避免多张接近原尺寸的半透明卡片在中心穿叠；透明度变化与外壳同时开始，不瞬间隐藏成员或增加成员显露等待。组合外壳从当前世界矩形连续变形到最新矩形，使用同一无回弹临界阻尼 spring；快速反向接管当前 presentation。组合拖动必须同帧冻结外框与成员的实际呈现矩形，然后由 React Flow 逐次更新整组位移，不能只冻结外框却把成员复位到动画终点。终端自身展开收起同样原位改变外壳与邻居布局，但保持已挂载终端内容的最终尺寸，避免每帧重新拟合 xterm 或调整 PTY。终端标题操作区在宽度过渡中裁切，并保留最右侧加减按钮；展开组合保留最右侧减号，折叠组合采用独立圆角图标底板与下方外置名称，整个折叠区域承担展开入口，不另设加号。组合外框与折叠图标底板复用同一层不透明材质，沿共享 spring 连续收缩或展开，不交叉淡化两套外壳；收起接近图标尺寸时，图标与名称才按同一进度显现，避免与正在回收的成员透叠。展开首帧保留无交互的图标与名称，随同一进度淡出后再显露标题栏；标题栏不绘制第二层背景，阴影也由该进度连续过渡，避免突现横条或阴影跳变。选中描边跟随同一材质几何；静止的折叠态不显示包住名称的外框，聚焦和拖入反馈贴合图标底板。`prefers-reduced-motion` 下直接投影相同最终状态。

BlockGraph 新状态先成为事实；收起时已经挂载的终端表面在成员抵达组合后进入不可见、不可交互的 Presentation 停放态，使同一工作区内再次展开可以复用 xterm surface，避免在空间运动的关键帧内集中创建、恢复和测量终端。初次载入时已经折叠的组合不得因此预挂载或自动启动终端；成员离组、组合解散或工作区切换时必须释放停放态。组合成员的空间 transform 只能作用于视觉表面，React Flow handle 与 resize 命中区必须留在不参与动画的最终锚点；停放成员不得参与小地图、键盘导航、选择聚焦或 fit-view。依赖线通过专用边组件跟随当前呈现矩形，不能让 React Flow 在临时 transform 上测量并缓存端点。节点 pointer down 可以让标题内容产生至多 `1px` 的即时下沉；直接拖动只用既有阴影提高视觉层级，不得在 Terminal、Agent 或 React Flow 组合节点根上设置会改变 xterm、resize 或坐标计算的常驻 transform，也不得为松手增加持续惯性或弹跳。该限制不包括下文由组合拖放 owner 临时写入视觉外壳的尺度反馈。

终端或完整流程拖入组合时，组合当前呈现的世界矩形在拖动开始时冻结，加入预览使用主题强调色实线，移出预览使用同色虚线，并提供简短提示，不缩放容器或被拖终端，也不在拖动中提交成员或扩大边界。接纳与离开使用固定矩形两侧的迟滞区。松手后通过同一 BlockGraph 入口提交归属，以固定组合锚点自动排版；成员与组合外壳从当前呈现位置同步收敛。无依赖终端标题与画布中每条流程上方的紧凑标签分别拖动独立终端和完整流程；组合内的流程单节点标题拖动只临时偏移，任何位置松手都回到原槽位，不提交坐标或成员变更；组合外的流程节点标题可自由拖动，松手保存释放位置，保留成员归属和依赖，连线持续跟随；标题拖动不被视觉堆叠或多选接管。组合内流程单节点松手沿共享 spring 回到原槽位，连线逐帧贴合节点，回位期间的数据刷新不得提前移除动效状态；不提交成员事务或重排邻居。流程标签保留抓取点偏移，并支持空格抓取、方向键移动、空格放下与 Escape 取消；移出只解除归属，不删除终端或依赖。折叠组合直接接收并保持折叠。Escape、取消和捕获丢失立即清理反馈、恢复预览，不提交；新拖动接管当前呈现位置。`prefers-reduced-motion` 下直接呈现相同最终结果。

依赖线使用三次 Bézier 曲线，通过节点最终几何与共享 spring 当前值更新路径，避免逐帧读取 DOM 布局，不把动画中间端点写回 React Flow 的 handle 测量缓存；跨边界依赖在组合折叠时连接到可见组合，内部依赖隐藏。

画布直接操控使用单一原生 CSS cursor token。空白 pane、平移、框选、三类节点选择与拖动、模板放置共享同一枚紧凑的无尾纸飞机指针；不根据按下或拖动状态切换 `grab`、`grabbing`、`move` 或 `crosshair`，也不创建随 `pointermove` 更新的 DOM 光标。纸飞机轮廓由左上尖端、右侧机翼、内收折角和下方尖角组成，不得带传统系统箭头的箭杆；使用深色主体与浅色细描边同时适应明暗画布，不叠加模糊光晕。热点必须落在左上尖端并提供系统箭头回退。统一规则不得覆盖 xterm、文本编辑、连接 handle、resize、按钮禁用与等待状态的语义指针。

终端标题中的描述始终隐藏并退出布局，名称和必要的工作流状态保持单行，不受降噪开关、缩放或交互状态影响。画布缩放分级只减少次要动作和地址等视觉噪声，不改变对象外框和空间占位，也不隐藏导航所需的名称、类型与关键状态。应用设置提供默认关闭的“减少视觉噪声”开关；关闭后所有 zoom 都投影完整细节，不能在消费者中复制一套反向可见性规则。resize 与连接 handle 沿用原有命中和可见性规则；其他被降噪的控件也必须保留命中区域和可访问路径，并在节点悬停、键盘聚焦或选中时显露，不得用 `visibility: hidden` 或禁用指针事件改变既有操作契约。设置变化必须只改变细节投影，不重建画布对象或中断交互。细节阈值属于统一 owner 的实现参数；消费者不得根据 zoom 另建近似阈值或改变持久化几何。

MCP 终端搭建的空间起点优先使用发起 Agent 的边缘，只有发起 Agent 不在当前投影中时才回退到最终落位附近最近的既有画布节点。相机先以发起 Agent 与本次已提交结果的最终边界完成一次可中断聚焦，节点随后从同一因果起点开始搭建；聚焦与搭建不得并行制造两套运动，也不得在逐步显露期间重复追踪。观看范围应保留来源与结果的关系，同时维持终端可读性；统一布局聚焦的最大缩放为 `100%`，较大边界继续自动缩小，不能继承画布 `160%` 的全局放大上限。距离异常时由统一相机 owner 的缩放边界约束结果，不在局部动效中另建镜头算法。

### 减弱动态效果

CSS 必须尊重 `prefers-reduced-motion`。JavaScript 驱动的 React Flow、滚动、Web Animation 或计时动画通过 `src/presentation/shared/motion/motionPreference.ts` 的单一订阅 owner 读取同一偏好，不能各自创建 `matchMedia`。偏好在运行中切换为 reduce 时，在途 motion 必须立即投影到当前意图的最终状态、清理 RAF 与最长时限，并保持既有焦点、互斥、提交次数和退出清理语义。

减弱动态效果不是删除信息：

- 大范围位移、缩放和旋转改为即时定位、短淡化或静态高亮。
- 持续装饰动画停止；spinner 改为静态进行图标，真实进行状态仍使用文字、图标或可访问属性表达。
- 焦点、选择、审批目标和错误状态继续清晰可辨。
- 业务完成、焦点恢复和测试同步不得依赖动画时长。

## 可访问性

第一方文案、可访问名称和不可翻译内容的具体归属由 [国际化规范](../i18n/README.md) 维护。

- 图标按钮必须有可访问名称；表单控件必须有标签；占位符不能替代标签。
- 键盘焦点始终可见，颜色不是状态或错误的唯一载体。
- 普通控件统一使用 `--cc-ring` 的中性焦点色，侧栏焦点 token 复用该颜色。有边框的输入框、文本域和搜索容器聚焦时只加深原边界，不叠加外侧轮廓或光晕；无边框按钮保留清晰的中性焦点轮廓，有边框按钮的轮廓向内绘制，与原边界合并。复合输入的文本输入区域由外层容器表达焦点，内部文本框不再描边。实心主按钮局部使用 `--cc-primary-contrast` 作为焦点色，保证内侧轮廓与按钮底色之间的对比。
- 主题选项与 Issue 筛选的选中态使用 `--cc-settings-selection-*` 中性色；主题保留勾号，筛选保留启用状态和表面差异。主题同时选中并获得焦点时仍只呈现一层边界。画布外的主要提交动作在深色主题使用浅灰色、浅色主题使用石墨灰，开关开启轨道均使用中性灰；正文链接保持蓝色和下划线，运行状态、流程连线和其余画布节点控件继续使用各自既有语义色。
- 菜单、对话框、浮层和可选择列表必须支持合理的 Tab、方向键、Enter 与 Escape 行为。
- 快捷键标签必须与实际平台绑定一致；不得展示尚未实现的快捷键。

## UI 评审清单

评审界面、截图或实现时，按影响从高到低检查：

1. 产品语义：界面是否表达真实对象、作用域、状态和结果，是否与 UI 契约一致。
2. 主要流程：用户是否能在合理步骤内完成高频目标，主要动作是否直接可见。
3. 信息层级：主内容是否获得最大面积，次要 chrome、卡片和说明是否过强。
4. 状态完整性：空、加载、禁用、焦点、选中、错误和恢复路径是否清晰。
5. 输入与键盘：终端、文本选择、画布手势、快捷键和焦点是否互不抢占。
6. 布局韧性：长文本、双语、窄窗口、滚动和浮层边界是否稳定。
7. 视觉一致性：颜色、阴影、按钮、图标、边框和相邻组件是否复用现有规则。
8. 动效：是否解释连续性、可被打断、尊重减弱动态效果且不影响性能。
9. 反馈真实性：进行中与结果是否由真实状态支持，错误是否给出下一步。
10. 桌面环境：浅色、深色、macOS 窗口安全区和真实 Electron 能力是否正确。

评审输出优先列出最影响用户目标的三项问题，再给出具体对象、风险和建议；不得用大量像素级意见掩盖产品语义、焦点、状态或操作路径问题。

需要实际渲染证据时，按 [测试规范：组件样式与真实渲染验证](../testing/testing.md#组件样式与真实渲染验证) 使用隔离 Electron 窗口挂载生产组件，具体步骤见 [隔离 Electron 组件样式检查](../testing/e2e-stability.md#隔离-electron-组件样式检查)。

- 局部 CSS、一次性排列或可演进视觉细节不写入本文。
