# 产品功能与快速上手

## 文档定位

本文面向第一次接触 cleancode 的开发者，回答三个问题：

1. cleancode 是什么。
2. 当前已经有哪些产品功能。
3. 常见开发场景应该怎样使用这些功能。

本文只记录当前代码已经实现的用户能力，不记录路线图，也不展开架构和实现细节。若本文与产品契约或上下文专文冲突，以文末列出的事实 owner 文档为准。

## 一句话认识 cleancode

cleancode 是一个画布优先、本地优先的可执行开发工作空间。它把本地项目、Git 分支工作区、交互式终端、依赖工作流和 Coding Agent 放到同一张画布上，让开发者可以直接搭建、运行和复用自己的开发现场。

```txt
本地项目
└── 分支工作区
    └── 画布
        ├── 终端、流程与组合
        ├── Coding Agent
        ├── 收藏模板
        └── 快捷执行位
```

cleancode 不是完整 IDE。它不提供文件树或代码编辑器，重点是组织并运行已有开发工具，以及让人和 Agent 共享同一个可见工作现场。

## 先运行起来

环境要求：

- Node.js `>= 24`
- pnpm `>= 10`
- macOS、Windows 或 Linux

```bash
pnpm install
pnpm dev
```

也可以直接从 [GitHub Releases](https://github.com/chen-985211/cleancode/releases) 下载 Preview。安装、签名提示和本地打包方式见根目录 [README 快速开始](../../README.md#快速开始)。

## 核心对象速览

| 对象       | 是什么                                | 常见用途                                |
| ---------- | ------------------------------------- | --------------------------------------- |
| 项目       | 一个本地项目目录                      | 把已有仓库加入 cleancode                |
| 默认工作区 | 项目根目录对应的固定工作面            | 在当前 checkout 上直接工作              |
| 分支工作区 | 独立 Git worktree 对应的工作面        | 并行开发功能、修复或实验分支            |
| 画布       | 当前工作区的空间工作面                | 摆放终端、组合和 Agent                  |
| 终端       | 最小执行单位和交互式本地 shell        | 运行构建、测试、服务和日常命令          |
| 流程       | 由依赖连线形成的一条完整终端依赖图    | 按顺序启动多个任务或服务                |
| 组合       | 可为空并容纳完整执行单元的终端空间    | 整理和批量操作一组开发命令              |
| Agent      | 固定 Provider 的本地 Coding Agent CLI | 编码、分析，以及通过 MCP 搭建画布工作流 |
| 收藏模板   | 终端、流程或组合的可复用配置快照      | 在项目内或跨项目复用开发现场            |
| 快捷执行位 | 当前工作区固定的五个运行快捷位        | 用快捷键启动常用终端、流程或组合        |

## 十分钟搭出第一条工作流

1. 点击左侧边栏的“添加项目”，选择一个本地项目目录。
2. 如果需要隔离开发，在项目下创建一个分支工作区；cleancode 会创建对应 Git worktree 并切换过去。
3. 在画布空白处右键选择“新建终端积木”，或使用 `Command/Ctrl + T`；再为终端填写名称、描述和启动命令。
4. 根据命令性质把终端配置为任务或服务：
   - 安装、构建、测试等会结束的命令使用任务。
   - 开发服务器、watcher 等持续运行的命令使用服务。
5. 从上游终端输出点连接到下游终端输入点，声明真实启动依赖。
6. 从根终端选择“从此处运行流程”，观察任务完成、服务就绪和下游启动。
7. 把这套流程收藏为模板，或添加到快捷执行栏，方便以后复用。
8. 如需 Agent 协助，在同一画布新建 Agent；支持的 Provider 可以开启 CleanCode MCP，让 Agent 直接检查和搭建这张画布。

## 功能清单

### 项目与分支工作区

当前支持：

- 添加、选择、排序和移除本地项目。
- 记住最近项目以及上次选择的项目。
- 为 Git 仓库创建独立分支工作区，每个工作区使用独立 worktree 目录。
- 在默认工作区切换已有 Git 分支。
- 在项目与工作区之间快速切换。
- 归档干净的分支工作区；归档会移除 worktree，但保留 Git 分支。
- 自动同步真实 Git 分支和 worktree 状态。
- 为每个物理工作区分别保存画布、终端会话和 Agent 会话。

常见用法：

- `main` 或默认分支上的日常工作直接使用默认工作区。
- 同时开发多个需求时，为每个需求创建独立分支工作区。
- 需要切换项目根目录的 checkout 时，在默认工作区选择已有分支。
- 分支工作区完成后先处理未提交改动，再执行归档。

当前不负责 Git 合并、变基、冲突解决、分支删除或远程仓库托管，这些操作继续使用现有 Git 工具。

### 画布与导航

画布支持：

- 创建、选择、多选、移动、调整大小和删除终端。
- 创建、选择、移动、调整大小、重命名和移除 Agent。
- 创建、移动、折叠、展开、编辑和解散终端组合。
- 保存终端位置、尺寸、组合状态和画布视口。
- 自动为新节点寻找不与现有对象重叠的位置。
- 平移、缩放和适应全部内容。
- 使用小地图查看画布分布、移动视口和定位对象。
- 使用方向快捷键在终端、组合和 Agent 之间进行空间导航。
- 使用右键菜单操作独立终端、完整流程或组合。

默认快捷键：

| 动作                 | macOS / Windows / Linux                                    |
| -------------------- | ---------------------------------------------------------- |
| 收起或展开侧边栏     | `Command/Ctrl + B`                                         |
| 添加项目             | `Command/Ctrl + O`                                         |
| 新建分支工作区       | `Command/Ctrl + N`                                         |
| 新建终端             | `Command/Ctrl + T`                                         |
| 新建 Agent           | `Command/Ctrl + Shift + A`                                 |
| 创建终端组合         | `Command/Ctrl + G`                                         |
| 选择相邻画布对象     | `Command/Ctrl + 方向键`                                    |
| 放大、缩小、适应画布 | `Command/Ctrl + ]`、`Command/Ctrl + [`、`Command/Ctrl + \` |
| 收起或展开小地图     | `Command/Ctrl + Shift + M`                                 |
| 上一个或下一个工作区 | `Command/Ctrl + Shift + ↑/↓`                               |

所有应用快捷键都可以在“应用设置 → 快捷键”中修改、清除或恢复默认。

### 终端

终端是 cleancode 当前最主要的执行积木。

#### 基本能力

- 在当前工作区目录启动真实交互式 shell。
- 输入命令并显示标准输出和标准错误。
- 保存名称、描述、启动命令和任务/服务执行配置。
- 执行已保存的启动命令，并防止同一终端重复启动。
- 用“停止当前命令”向当前 PTY 发送 `Ctrl+C`。
- 用“重开空终端会话”替换旧会话、清空输出并回到空 shell，不执行已保存启动命令。
- 调整终端大小，并同步真实 PTY 行列。
- 在命令结束、失败、超时或停止后保留最终输出。
- 普通直接启动命令结束后回到同一可输入 shell；工作流任务结束后保留为已结束历史。

#### 搜索、复制、粘贴与链接

- `Command/Ctrl + F` 搜索当前终端保留的可读历史，并支持上一项和下一项。
- 选中文本后使用复制快捷键复制；没有选区时，`Ctrl+C` 保持终端中断语义。
- 粘贴会规范化换行并处理大文本；高风险控制字符和剪贴板文件路径会先请求确认。
- 按住 `Command/Ctrl` 点击终端自动识别的 HTTP/HTTPS 链接或工作区内文件路径。
- 外部 CLI 提供的 OSC 8 超链接可以直接单击，但仍只允许安全协议和授权路径。
- 支持 IME、CJK、emoji 和 Unicode 终端宽度处理。

#### 会话、历史与恢复

- 在独立分支工作区之间切换时，仍运行的普通终端继续运行；返回后可以看到离开期间的输出。
- 普通交互终端和非工作流直接启动会话可以按当前会话开启“应用退出后继续运行”。
- 应用重开后，符合条件的会话会恢复为可输入的 live 会话；进程已经不存在时保留为只读历史。
- 工作流会话和 Agent terminal 不支持跨应用继续运行。
- 删除终端、归档物理工作区或移除项目会终止对应会话并清理恢复资料。
- 终端滚动历史可以在 1000、5000 和 10000 行之间选择。

### 任务、服务与端口

终端启动命令可以配置为任务或服务。

任务适合安装、构建、测试和生成文件：

- 默认以退出码 `0` 为成功。
- 可以配置多个成功退出码。
- 可以配置运行超时。
- 真实退出码不符合规则或发生超时时，任务失败。

服务适合开发服务器、代理和 watcher：

- 可以等待指定输出文本出现后进入就绪。
- 可以等待本机 TCP 端口开始监听后进入就绪。
- 可以配置就绪超时。
- 就绪后继续运行，并允许下游开始。

需要管理端口时，可以选择：

- 固定端口：必须使用指定端口，冲突时失败。
- 首选端口：优先使用指定端口，冲突时自动回退。
- 自动端口：每次运行动态分配。
- HTTP、HTTPS 或 TCP 协议。
- 通过环境变量或包含 `{port}` 的命令参数把最终端口注入服务。

cleancode 会展示本次运行的实际回环端点，并在停止服务时等待监听关闭后释放端口。

### 终端依赖工作流

工作流由终端之间的有向依赖连接形成：

- 连线方向是“上游 → 下游”。
- 不允许自连接、重复连接或形成环。
- 没有上游的根任务可以并行启动。
- 下游等待全部直接上游成功或就绪。
- 一个分支失败只阻塞自己的后代，不影响无依赖的其他分支。
- 任务通过退出码判断成功，服务通过就绪条件放行下游。
- 工作流状态包括等待、运行、就绪、成功、失败、阻塞和已停止。
- 同一工作区同一时间只保留一个活动工作流。

常用启动入口：

- “启动命令”：只运行当前终端，不启动下游。
- “从此处运行流程”：运行当前终端及其全部后代。
- “启动组合命令”：运行组合内精确成员，并保留内部依赖。
- “放置并运行”：创建模板实例后运行这次新建的精确成员。
- `Command/Ctrl + 1` 至 `5`：运行对应快捷执行位。

工作流运行时，右上角通知显示进度并提供“停止本次运行”。停止会阻止新的节点启动，按反向依赖顺序停止活动进程，并保留各终端已经产生的输出。

### 终端组合

终端组合用于组织和批量管理开发命令，本身不是工作流节点，也不创建新的 PTY。

当前支持：

- 创建可持续存在的空组合，并把独立终端或完整流程拖入其中。
- 组合可以同时包含独立终端和多条完整流程。
- 编辑组合名称、移动、折叠和展开组合。
- 添加或移出成员；命中流程中的任意终端时按完整流程处理。
- 按内部依赖启动组合全部成员。
- 停止组合成员的当前命令。
- 为组合成员重开空终端会话。
- 解散组合并保留全部成员终端。
- 移除组合及其全部成员终端。

如果只想取消视觉组织，使用“解散组合”；如果要同时删除成员终端，使用“移除组合”。

### 收藏模板

收藏模板用于复用终端配置和依赖结构。

可以收藏：

- 一个独立终端。
- 一条完整依赖流程。
- 包含多个顶层执行单元的组合。

常见操作：

1. 右键终端、流程或组合并选择对应收藏动作；也可以按住 `Command/Ctrl` 在画布空白处框选终端。
2. 选择保存到当前项目或全局收藏。
3. 在窗口右上角打开收藏模板库。
4. 搜索、重命名、删除模板，或在项目与全局作用域之间移动。
5. 选择“放置”或“放置并运行”，再在画布上指定期望位置。

模板保存名称、描述、启动命令、执行配置、内部连接和相对布局，不保存终端输出、PTY、运行状态、实际端点、Agent、Agent 对话或画布视口。每次放置都会创建拥有新身份的独立实例。

### 快捷执行栏

每个工作区画布底部都有 `1` 至 `5` 五个快捷执行位，可以绑定独立终端、完整流程或组合。

- 从首个空位打开对象列表进行绑定。
- 把终端或组合拖入快捷执行栏；流程中的终端会按完整流程绑定。
- 从终端、流程或组合右键菜单选择“添加到快捷执行栏”。
- 新对象自动占用编号最小的空位；五格已满时不会覆盖已有绑定。
- 拖动快捷位可以交换或移动位置。
- 拖到临时出现的垃圾桶可以清空绑定。
- 对象结构变化后，失效绑定会保留并显示为不可用，等待重新绑定或清除。
- 单击快捷位只定位画布对象；只有 `Command/Ctrl + 1` 至 `5` 才执行。

快捷执行位按物理工作区分别保存，关闭应用或切换工作区后仍会恢复。

### Coding Agent

Agent 是画布内固定 Provider 的本地 CLI 控制台，不是普通终端，也不能加入终端组合。

当前支持：

- 在一个工作区创建零个或多个相同或不同 Provider 的 Agent。
- 自动检测本机已经安装的 Provider CLI，并只把可用项放入新建菜单。
- 为每个 Agent 固定 Provider、名称、位置、尺寸、终端和对话绑定。
- 直接使用真实 Provider CLI 的输入、输出和 TUI。
- 重命名、移动、调整大小、重新启动、开始新对话和移除 Agent。
- 在 Agent 设置中选择默认 Provider、启用或禁用 Provider，并配置命令、附加参数和环境变量。
- 选择 `Yolo` 或手动权限模式，并设置新 Agent 是否默认启用 CleanCode MCP。
- 在工作区之间切换时隔离 Agent；同一工作区的多个 Agent 共享目录和文件。

cleancode 当前内建 33 个 Coding Agent Provider，完整列表见根目录 README 的 [Agent Provider 列表](../../README.md#带上你喜欢的-agent)。Codex、Claude Code、OpenCode 和 Gemini 当前提供正式会话引用与恢复，并支持 CleanCode MCP；其他 Provider 按各自声明的能力工作。

#### CleanCode MCP

支持的 Agent 可以通过头部开关连接 cleancode 原生 MCP。开启后，Agent 可以：

- 读取当前画布、终端、连接、组合和执行计划。
- 一次性创建、配置、连接、组合、排列并校验完整终端工作流。
- 增量创建、编辑和删除终端。
- 创建、编辑和解散终端组合。
- 配置任务、服务和端口意图。
- 建立或断开依赖。
- 检查工作流计划并整理终端布局。

删除终端、解散组合和断开依赖需要在 cleancode 界面审批。MCP 当前只能搭建和检查工作流，不能启动、查询或停止工作流；Agent 完成搭建后仍由用户决定是否运行。

Agent 一次创建完整工作流后，画布可以按“逐步搭建”或“并行进入”连续呈现结果。拖动对象、平移或缩放会立即把控制权交还用户；开启系统减少动态效果后直接显示最终布局。

### 语言、主题与应用设置

当前支持：

- 简体中文和英文界面，并记住语言偏好。
- 跟随系统、浅色和深色三种主题偏好。
- 主题切换时保持终端和 Agent 会话，不重启 PTY。
- 在应用设置中调整终端滚动历史、工作流搭建动效和快捷键。
- 自定义、清除、恢复单个快捷键，或恢复全部默认值。
- 在 Agent 设置中管理 Provider、权限模式、启动覆盖和 MCP 默认值。

## 常见使用方法

### 同时启动前端和后端

1. 新建“安装依赖”任务、“启动后端”服务和“启动前端”服务。
2. 把安装依赖连接到两个服务；如果前端确实依赖后端就绪，再连接后端到前端。
3. 为后端和前端配置输出文本或 TCP 就绪条件。
4. 需要避免多工作区端口冲突时，使用首选或自动端口，并配置项目真实支持的环境变量或参数注入。
5. 从“安装依赖”选择“从此处运行流程”。

### 并行开发两个需求

1. 在同一个项目下分别创建两个分支工作区。
2. 为每个工作区保留独立画布、终端和 Agent。
3. 使用工作区快捷键来回切换；普通终端会继续运行并保留输出。
4. 某个需求完成后，确认工作树干净再归档对应工作区。

### 复用团队常用流程

1. 把安装、构建、测试和开发服务器连接成流程。
2. 收藏为项目模板，供当前项目的其他工作区复用；需要跨项目使用时移动到全局收藏。
3. 选择“放置并运行”快速创建一套新实例并启动。
4. 把最常用实例加入快捷执行栏，用 `Command/Ctrl + 数字` 日常启动。

### 让 Agent 帮忙搭建工作流

1. 新建支持 CleanCode MCP 的 Agent 并开启 MCP。
2. 可以这样描述需求：“查看当前项目，帮我在 CleanCode 画布搭建安装、后端和前端终端，配置依赖与服务就绪条件。”
3. Agent 会先检查画布，必要时读取项目以确认真实启动命令，再通过 MCP 提交完整工作流。
4. 检查画布上的终端、依赖、端口配置和计划。
5. 由你选择终端、组合、模板或快捷执行位启动工作流。

### 保留一个长时间运行的普通终端

1. 在普通交互终端或非工作流直接启动会话中开启“应用退出后继续运行”。
2. 正常退出 cleancode。
3. 下次打开应用时，仍存活且完成 checkpoint 的会话会恢复为可输入状态。
4. 如果进程已经结束，终端会恢复为只读历史；需要新环境时使用“重开空终端会话”。

该能力不适用于工作流会话或 Agent terminal。删除终端、归档工作区和移除项目始终会执行清理。

## 当前边界

- 当前可执行积木以终端为核心；Preview、HTTP、Test、File 和 Plugin 等独立积木类型尚未实现。
- Agent 和终端组合不是工作流节点。
- 工作流不会自动在节点之间传递标准输出、文件或结构化产物。
- 活动工作流不会跨应用重启恢复。
- CleanCode MCP 不能启动、查询或停止工作流。
- 当前不支持远程主机、分布式执行或跨项目工作流。
- 插件扩展体系尚未公开，不承诺第三方插件兼容性。
- Git 合并、变基、冲突解决和远程仓库操作继续由外部 Git 工具承担。
