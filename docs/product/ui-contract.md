# UI 契约

## 文档地位

本文定义 cleancode 工作台长期有效的用户界面契约，包括信息架构、对象语义、用户能力、关键交互不变量和反馈行为。

本文只回答“产品中的界面对象是什么、用户可以做什么、系统必须保持哪些可见不变量”。视觉角色、组件选择、动效方法、状态设计和评审流程以 [UI Style Guide](ui-style-guide.md) 为准；具体 DOM、CSS、图标、按钮排列和临时文案由当前实现与行为测试证明；尚未确认或尚未交付的方向统一记录在 [UI 路线图](ui-roadmap.md)，不得从路线图推导当前功能已经存在。

本文不是当前界面的截图说明、组件实现清单、版本验收记录、设计素材库或产品路线图。Style Guide 不得反向改写本文定义的产品语义；实现细节也不得因为当前样式如此就自动升级为长期契约。

本文不定义架构规则、测试组织、组件实现或工程流程。

本文中的“必须”和“不得”表示稳定约束。用户确认的 UI 调整改变这些约束时，代码、测试和本文必须在同一任务中对齐；发现三者冲突时不得静默沿用旧描述。

## 产品定位

cleancode 的 UI 是画布优先的本地开发工作台。

用户进入项目后应直接看到工作画布，并能通过分支工作区、终端积木和 Agent 控制台完成真实本地开发活动。界面不得退化为营销欢迎页、文件管理器、聊天应用或完整 IDE。

## 信息架构

工作区是应用窗口默认的顶层内容区域，并必须填满可用的窗口内容区。应用级入口可以作为窗口级控件叠加在工作区之上，但不得形成独立的常驻栏或占用工作区布局。全屏应用设置是临时替代工作区视觉层级的窗口内设置面，不是独立窗口；打开时原工作区必须保持挂载并停止交互：

```txt
应用窗口
  ├─ 工作区：填满窗口内容区
  │   ├─ 左侧边栏：项目与分支工作区
  │   └─ 主工作区：积木画布
  │       ├─ 画布导航与操作
  │       ├─ 终端积木与终端组合
  │       └─ Agent 控制台（固定 Provider）
  ├─ 窗口级入口：按内容宽度叠加，不形成独立常驻栏
      ├─ 语言设置入口
      ├─ 主题设置入口
      ├─ 应用设置入口
      └─ 应用通知
  └─ 全屏应用设置：临时覆盖工作区
      ├─ 左侧设置导航
      └─ 当前设置内容
```

主画布必须占据窗口的主要面积。Agent 控制台位于画布内，不得恢复为固定右侧栏。

窗口级入口与画布操作必须保持两层信息层级：语言、主题和应用设置入口位于窗口右上第一层，画布创建和组合操作位于其下方的第二层。后续应用级设置必须进入全屏应用设置，不得把新的设置入口与画布操作混排；两个窗口级控件层都必须按内容宽度占位，不得恢复为横跨窗口的标题栏。工作流发起动作属于终端对象，活动运行的状态和停止动作属于应用通知，不得混入第二层画布工具栏。应用通知从窗口右上角临时叠加，不占用工作区布局，并必须避让可操作的窗口级入口。

采用隐藏标题栏的平台必须只为原生窗口控件保留必要的局部安全区和窗口拖拽能力。该区域不得扩展为横跨窗口的常驻标题栏或全宽拖拽区，不得覆盖主画布的交互面或吞掉画布指针操作。

界面不得增加与当前开发工作无关的常驻区域，例如文件树、底部全局 Dock、营销式 Hero 或装饰性侧栏。新增长期区域前必须先确认它的用户目标和信息层级。

## 语言与本地化

窗口右上第一层必须提供语言设置入口，并紧邻在主题设置入口左侧。入口与语言菜单不得占据工作区布局；菜单必须明确标识当前语言，支持键盘导航、Escape 关闭、点击外部关闭，关闭后恢复入口焦点。

应用固定支持简体中文和英文。没有显式偏好时，系统首选语言为中文时使用简体中文，其他情况使用英文；用户显式选择必须跨应用重启恢复。切换后，所有第一方界面文案、可访问名称、表单验证、错误映射和后续操作反馈必须立即使用当前语言，并同步文档的语言属性。

项目名、分支名、路径、已保存的终端或 Agent 名称、用户输入、命令、终端输出和 Agent 输出都是用户或外部系统内容，不得被界面本地化翻译或重写。切换语言不得重建终端或 Agent 会话，也不得修改项目、工作区、画布或运行状态。

locale catalog、Message key、文案归属、不可翻译边界和 AI 修改要求以 [国际化规范](../i18n/README.md) 为准。

## 主题偏好与切换

窗口右上第一层必须提供唯一的主题设置入口。入口不得占据工作区布局或形成常驻栏；默认状态必须低噪声但仍可发现，在悬停、键盘聚焦和打开状态下必须提供明确反馈。主题设置以不改变画布布局的右侧抽屉展示；抽屉打开时背景工作区不得继续接受交互，关闭后焦点必须回到入口。

主题偏好固定包含“系统”“浅色”和“深色”三种状态。首次使用默认为“系统”，用户选择必须跨应用重启恢复。选择“系统”时，有效主题必须跟随操作系统并响应运行中的系统主题变化；选择“浅色”或“深色”时，有效主题不得被系统变化覆盖。

主题必须覆盖主题设置入口、侧边栏、画布、终端积木、终端组合、Agent 控制台、小地图、菜单、表单、弹窗、提示和 xterm 内容。主题切换不得重建终端或 Agent 会话，也不得修改项目、工作区或画布业务状态。xterm 已缓冲的原始真彩色输出必须保持为统一可读的主题外观，不得在切换后混合展示切换前后的明暗配色。同一 Agent PTY 或普通终端 generation 运行期间，其终端源 palette 必须保持为创建时的主题；离开再返回工作区时必须沿用原 source，通过统一视觉转换匹配当前应用主题，不得用当前主题冒充仍在运行的 PTY 源主题。xterm 转换后的最终背景必须与当前主题的上、左、下阅读留白形成完整、连续的终端平面，切换后不得在内容三侧留下不同颜色的窄带；右侧 viewport 和滚动条仍须贴住内容外框。搜索、粘贴确认等第一方覆盖层继续使用当前应用主题，不随外部 CLI 内容反色。普通终端在可见和隐藏状态下对默认前景、背景查询的回答必须一致且只有一个响应者，避免其中启动的 Codex CLI 缓存错误主题。

这里的主题覆盖保证应用 chrome、终端宿主 surface、默认 palette、光标、选区和运行时内容的整体可读性，不承诺把外部 Provider CLI 重绘成相同品牌或相同像素。Codex、Claude Code、OpenCode 或其他 CLI 自己输出的 ANSI/真彩色语义、TUI 布局和用户保存的 CLI 主题仍属于对应 CLI；cleancode 不得为追求外观一致而修改用户全局 Provider 配置，也不得在 Presentation 中按 Provider ID 添加专属视觉分支。

尚未提供的颜色预设、字体、圆角和密度选项不得以空分组、禁用项或占位内容出现在主题设置中。

## 应用设置与快捷键

窗口右上第一层必须在主题入口右侧提供应用设置入口，并作为这组入口最右侧的控件。应用设置在当前窗口内以全屏设置面呈现，必须包含独立返回动作、左侧可扩展导航和当前设置内容；导航只展示已经交付的设置项，不得用空分组或禁用占位暗示尚未实现的能力。关闭后焦点必须回到应用设置入口。

应用设置打开期间，项目边栏、画布、普通终端、Agent 控制台和其他工作区内容必须保持挂载但停止交互；退出设置后必须继续使用原有工作区、PTY、xterm、Agent 和画布状态，不得通过重建工作区模拟返回。

终端是应用设置中的独立条目。当前滚动历史预设固定为 1000、5000 和 10000 行，首次使用及损坏、未知或越界的持久化值回退到 1000 行。修改后必须立即作用于当前及后续普通终端的权威模型、snapshot 和可见视图，不得要求重启应用或替换会话。

快捷键是应用设置中的一个条目，不是整个设置面的独立产品层级。当前可配置目录和默认键位固定为：

- 应用与项目：打开设置 `Command/Ctrl + ,`、切换侧边栏 `Command/Ctrl + B`、添加项目 `Command/Ctrl + O`、新建分支工作区 `Command/Ctrl + N`、上一个工作区 `Command/Ctrl + Shift + ↑`、下一个工作区 `Command/Ctrl + Shift + ↓`。
- 画布创建：新建终端 `Command/Ctrl + T`、新建 Agent `Command/Ctrl + Shift + A`、组合终端 `Command/Ctrl + G`。
- 画布导航：选择左、右、上、下方向的节点分别使用 `Command/Ctrl + ←/→/↑/↓`，放大画布 `Command/Ctrl + =`、缩小画布 `Command/Ctrl + -`、适应画布 `Command/Ctrl + 0`、收起或展开小地图 `Command/Ctrl + Shift + M`。

用户修改或清除键位后必须立即生效并跨应用重启恢复；损坏、不完整或存在冲突的当前版本持久化偏好必须整体回退到默认目录。快捷键偏好 schema v4 的旧版完整目录升级到 schema v5 时，四个画布移动动作的已有自定义或清除状态必须迁移到对应的方向节点选择动作；更早版本升级时必须保留已有自定义或清除状态，并为新增动作补充不冲突的默认键位。新增默认键位与旧自定义绑定冲突时，新增动作保持未分配。

快捷键录制必须要求包含 `Command`、`Ctrl` 或 `Alt` 的安全组合，并明确支持取消、清除、单项恢复默认和全部恢复默认。新组合与其他动作冲突时必须保留原绑定并就地说明冲突归属。全局监听只在应用聚焦范围内复用既有动作及其可用条件，不得成为系统级快捷键；输入框、文本编辑区和 xterm 不得触发画布方向节点选择外的应用动作，快捷键录制状态和模态界面不得触发任何应用动作。所有应用快捷键必须忽略键盘自动重复；终端获得焦点时，`Command/Ctrl + 方向键` 必须优先执行画布空间导航，不得写入 xterm 或移动 React Flow 节点。

方向快捷键在终端积木、终端组合和 Agent 控制台之间进行空间导航。存在整体选择时以当前对象中心为起点，否则以当前视口中心为起点；候选对象必须位于目标方向，同轴重叠优先，再按主轴与正交轴距离选择，距离相同时保持稳定的画布节点顺序。没有候选对象时保持当前选择，不得首尾循环。选择必须复用三类对象既有的互斥选择状态；每次通过方向快捷键选中目标后，选中状态和主输入必须立即生效，视口在默认保持当前缩放的同时以短促、可打断的空间过渡将目标中心定位到视口中心，不得添加惯性、弹跳或无法接管的连续移动。输入激活后仍必须可以连续使用方向快捷键导航；用户偏好减弱动态效果时，视口必须即时定位。只有目标在当前缩放下超出画布可辨识安全区域时，才允许同步缩小到能够完整辨识目标并保留周边空间的比例，不得因此自动放大目标。上一个和下一个工作区按侧边栏的项目与工作区顺序首尾循环，切换必须复用分支工作区的既有生命周期并串行执行；目标项目与侧边栏必须在导航后保持可见。新建分支工作区快捷键只作用于当前项目，并复用侧边栏既有表单；添加项目快捷键复用既有目录选择流程。

## 分支工作区

分支工作区是用户理解项目开发状态的主要边界：

```txt
一个分支工作区 = 一个完整工作面
```

完整工作面包含该工作区的积木图、终端积木、终端会话和 Agent 会话。切换分支工作区时，这些内容必须一起切换，不得串用其他工作区的会话或画布状态。

在独立 worktree 工作区之间往返时，仍在运行且未被生命周期操作替换的普通终端必须恢复同一会话及其有界可滚动输出；离开工作区期间到达的输出也必须在返回后可见。该保留不跨越终端重开或删除、工作区归档、项目移除和默认工作区真实 Git 分支替换；这些动作必须按各自生命周期停止或清理对应会话与输出。应用退出默认同样停止会话，只有用户对当前普通/直接启动会话明确选择“应用退出后继续运行”时才允许跨应用保留；Agent terminal 和工作流会话永远不能启用该保留，退出时必须由 Provider 作为终止候选处理。

返回工作区时，普通终端必须向 Run 查询本地缓存会话的权威状态。已退出会话不得因旧 renderer 状态重新显示为运行中，也不得因 xterm 重新 fit 而产生可见的“session not running”错误；迟到响应只能更新相同完整运行身份。

默认工作区以 `main` 作为稳定工作区名称。`main` 可以绑定真实 Git 分支；绑定状态不得制造另一个并列的“默认工作区”条目。项目尚未初始化 Git 时，侧边栏必须以“Git 未初始化”替代虚假的分支名，并保留“默认工作区”身份；初始化后显示真实绑定分支。

Agent 对话以“项目 + 工作区 + 当前 Git 分支 + Agent 身份”为隔离范围。默认工作区名称保持为 `main` 时，检出不同真实 Git 分支仍然属于不同 Agent 对话；同一分支的不同 Agent 也不得串用对话。切回原分支必须为每个 Agent 恢复其已经持久化的对话绑定。

独立 worktree 是实现隔离的技术手段。UI 可以通过辅助信息表达工作区类型，但不得把 worktree 路径提升为主要用户概念。

归档分支工作区属于破坏性操作，必须二次确认并明确说明：归档会移除 worktree 目录但保留 Git 分支。归档当前工作区时还必须说明将先切回默认工作区。

如果真实 Git 状态表明 worktree 已锁定，确认框必须展示锁定原因、目录会被移除但 Git 分支会被保留，并把主操作明确命名为“解除锁并归档”。该确认只适用于当前看到的锁状态；锁原因变化后不得静默复用。脏工作树即使已锁定也必须拒绝归档，不得向用户提供强制删除入口。

## 左侧边栏

左侧边栏只承载项目和分支工作区导航，以及与它们直接相关的操作。

左侧边栏必须提供：

- 添加和移除项目。
- 通过拖动项目标题调整项目顺序。
- 项目列表与每个项目的分支工作区列表。
- 当前项目和当前分支工作区的明确选中状态。
- 创建、切换和归档分支工作区的入口。
- 在默认工作区选择或检出可用 Git 分支的入口。

侧边栏整体必须可以通过常驻在窗口左上标题栏安全区域内的明确控件或 `Command/Ctrl + B` 收起和展开。该控件属于独立且常驻的标题栏导航区，不得作为侧边栏内容或画布浮层；在 macOS 普通窗口中紧跟系统窗口按钮，位置不得随侧边栏宽度或折叠状态漂移；进入原生全屏后必须释放不再需要的系统窗口按钮安全区并自动贴近窗口最左侧，退出全屏后恢复普通窗口位置。整体折叠只改变导航可见性与画布可用宽度，必须保留侧边栏、画布、PTY、xterm 和 Agent 的现有挂载与运行状态；折叠后仍必须保留可发现、可交互的展开控件。

侧边栏与主画布必须始终表现为同一张连续工作面。展开时不得使用贯穿高度的硬分隔线切开工作面；折叠后，常驻标题栏控件周围不得出现独立边框、底线、阴影或不透明容器形成的浮框感。边界只通过内容排布、克制的表面层级和交互状态暗示，不得让折叠动作显露新的壳层轮廓。

每个项目标题必须作为该项目的披露控件：单击项目名称只收起或展开其分支工作区列表，不得切换当前工作区。不同项目的折叠状态彼此独立；收起项目时关闭该项目内尚未提交的临时菜单或表单，重新展开后仍展示原有工作区事实。项目操作按钮必须保持独立作用域，不得因标题点击被误触发。侧边栏整体折叠与项目级折叠都是当前应用会话内的表现层状态，不得写入 Project 持久化事实。

项目标题同时是项目排序的拖动入口。普通单击继续只控制项目级折叠，只有指针移动超过拖动阈值后才进入排序；新建分支工作区、移除项目及其他项目操作不得触发拖动。拖动时必须以完整项目区块为排序单位并展示明确插入位置，取消或放回原位不得保存。成功排序只改变项目登记簿的持久化顺序，不得切换当前项目或当前工作区；保存失败时继续展示已提交顺序并给出可理解的错误反馈。

项目名、分支名和工作目录等长文本必须安全截断或折行，不得撑破布局。工作区类型、当前状态和不可用原因必须通过文字、图标或辅助属性表达，不得只依赖颜色。

移除项目必须二次确认，并明确说明：该操作会从 cleancode 项目列表中移除项目并停止其终端和 Agent 会话，但不会删除本地项目目录或 Git 数据。

## 主画布

主画布是终端、终端组合和 Agent 控制台的空间工作面。

画布必须支持：

- 展示当前分支工作区的积木图。
- 创建、选择、多选、移动、调整大小和删除终端积木。
- 保存积木图、终端位置与大小，以及画布视口。
- 创建、选择、移动、折叠、展开和解散终端组合。
- 创建、展示、选择、重命名、移动、调整大小和移除 Agent 控制台。
- 在重新进入工作面后恢复已经持久化的画布事实。

终端积木、终端组合和 Agent 控制台的整体选择只能由顶部标题区域触发；标题中的操作控件只执行自身动作，正文交互不得隐式选择整体。普通整体选择在三类对象之间必须互斥；终端多选只允许通过明确的多选操作形成。单击画布空白区域必须清除当前终端、终端组合和 Agent 的整体选择。Agent 的选中反馈必须限制在边框、阴影或其他正文外层，不得用覆盖层改变 xterm 正文颜色；清除选择不得重建终端视图或造成正文闪烁。终端积木和 Agent 控制台不要求预先选中，用户靠近任一角即可直接调整大小。终端正文必须允许选择和复制文本，正文内的文本拖选不得触发节点移动或画布平移；存在文本选区时复制快捷键只复制选区，没有选区时 `Ctrl+C` 必须保留终端中断语义。

Agent 整理终端布局时，只能移动本次工作流的精确终端作用域及完整包含它们的终端组合。布局以发起 Agent 的已保存位置为锚点，在其下方按依赖层级从左到右、同层从上到下稳定排列，并使用对象真实尺寸与固定留白避开发起 Agent、其他 Agent、无关终端和无关组合；不得移动 Agent 或把无关对象吸入布局。组合必须以完整外框作为视觉单元参与，不能与同批普通终端或其他组合重叠，排列后统一重算边界。

布局提交不得覆盖用户正在进行或已经先提交的拖动：普通终端以自身为保护单位，组合任一成员被用户移动时保护整个组合，其余未冲突目标仍可完成排列。只有实际发生布局变化时，画布才在新图完成投影且相关拖动保护结束后，对发起 Agent 与可见排列结果执行一次适应视图；幂等结果不改变视口，聚焦不改变现有选择，也不持久化为新的业务事实。

画布工具必须位于主工作区内，并与窗口级设置分层放置。没有当前项目或桌面运行时不可用时，依赖真实项目、文件系统、PTY 或 Agent 的操作必须禁用或展示明确空状态。

浏览器预览只能用于展示界面，不得伪造真实项目、终端或 Agent 能力。

## 小地图

小地图是画布的空间导航视图，不是内容预览器。

小地图必须：

- 用简化图形表达已经纳入导航的画布对象，包括终端积木、折叠终端组合和 Agent 控制台。
- 展示当前画布视口，并支持缩放、适应画布、收起、展开和视口移动。
- 支持从可导航缩略对象定位到对应画布对象；定位时必须根据对象真实尺寸保持可辨识的周边空间，不得把过大的对象强制放大到遮蔽画布上下文。
- 用克制的状态差异表达选中、悬停、运行和失败，不得让状态色替代对象身份。

展开的终端组合以成员终端作为主要导航对象，不额外强调组合外框；折叠的终端组合以一个组合缩略块表达，并保留成员摘要语义。

通过小地图定位终端积木或 Agent 控制台时，必须选择并显露对应画布对象，在定位过渡完成后同时激活其主输入。输入激活后的画布方向快捷键必须继续走统一的空间导航逻辑，不得因入口来自小地图而分叉。

Agent 控制台在小地图中只显示中性的空间占位和身份。小地图不得展示终端输出、Agent 对话、授权内容、完整属性或文件内容。

## 终端积木

终端积木是在画布上承载交互式本地终端会话的运行对象。

终端积木必须支持：

- 显示名称、描述和未启动、运行中、已退出、失败等会话状态。
- 区分新会话、实时恢复、只读历史和已结束；不得把历史画面显示为仍在运行。
- 配置并执行启动命令。
- 输入命令并显示标准输出和标准错误。
- 停止当前命令。
- 重开空终端会话。
- 编辑信息、调整大小和删除。

终端会话的工作目录必须来自当前分支工作区对应的本地目录。

终端主要操作应直接可发现，低频会话管理动作可以进入更多菜单。

运行中的普通交互终端和非工作流直接启动会话必须提供会话级退出保留开关，默认关闭。开关只作用于当前 session；用户从已开启保留的当前普通会话执行“启动命令”时，replacement 创建的非工作流直接启动会话必须继承开启状态，并在新 session 的恢复 checkpoint 确认成功后才显示为已开启；失败时新命令继续运行、开关保持关闭并提供本地化错误反馈。重开空会话、新建终端、工作流启动及其他 replacement 或新 generation 仍回到默认关闭。工作流会话、历史和已结束会话不可启用；工作流运行期间的保留控件必须保持不可执行，但允许鼠标和键盘用户通过 tooltip 得知它会随应用退出停止、不能跨应用保留。运行中持久化后来失效时，界面必须同步回关闭状态，不能继续承诺跨应用恢复。

Electron 正常退出流程等待运行时清理的默认预算为 5 秒。该预算只限制应用为清理而阻塞退出的时间，不是全部 PTY 已物理退出的用户承诺；达到预算后，独立 Provider 必须继续持有尚未安全完成的会话并完成终止或 checkpoint，不能为了更快退出丢失 owner、恢复证据，或让仍运行的默认策略、Agent 和工作流会话在下次启动时被误认作可恢复会话。

应用重开优先恢复同一个仍存活 session，并以“已恢复”表达可继续输入的 warm attach；Provider 不再存活时只显示“历史”及有界 normal-buffer 内容，输入、Ctrl+C 和运行中动作不可用；自然结束显示“已结束”；没有恢复资格时新建 shell 显示“新会话”。renderer 故障只重建窗口与视图，不替换同一 live session。显式关闭、删除终端、归档/checkout 工作区和移除项目始终终止后台会话并撤销恢复资料，即使退出保留已经开启。

终端运行时恢复完成前，画布状态栏必须显示“正在恢复终端运行时”，所有终端积木保持恢复等待态且不得自动或手动创建新 shell。恢复失败时状态栏显示“终端运行时不可用”，并只保留一条不自动消失的应用级错误通知；可恢复错误提供“重试恢复”，重试期间禁止重复提交。重试成功后通知消失，renderer 必须先按新的 runtime epoch 完成会话对账，再让确实没有 warm/historical 身份的终端恢复自动启动。不得把一次初始化失败表现为若干互不关联的终端启动失败，也不得继续显示“已连接本地运行时”。

### 日常检索、导航与输入

普通终端必须提供以下稳定交互：

- `Command/Ctrl + F` 打开局部搜索；输入时增量查询当前模型保留范围内的可读历史，显示结果计数，并支持上一项、下一项、Enter 与 `Shift + Enter` 导航。Escape 关闭搜索、清除高亮并把焦点交还终端；snapshot 恢复后仍可继续使用搜索。
- URL 只允许打开 HTTP/HTTPS 目标。工作区内文件路径可以携带行号和列号，但必须在打开前重新校验完整运行身份、当前工作目录和真实路径；不存在、失效、越出当前工作区或通过符号链接逃逸的目标必须拒绝，并在当前终端附近给出反馈。
- 链接只在按住 Command 或 Ctrl 时激活，普通单击继续用于终端光标、选择和 TUI 鼠标交互。
- 可见终端与隐藏权威模型使用相同的 Unicode 11 宽度规则。IME composition 和候选阶段由终端输入链路处理，候选中的 Enter、Escape、Backspace、复制或搜索组合键不得被应用快捷键提前截获。
- 文本粘贴统一规范化换行并按 UTF-8 边界分片，单次最多 1 MiB，支持进度和取消；终端启用 bracketed paste 时，成功、取消或失败都必须闭合协议。包含高风险控制字符的文本和剪贴板文件路径必须先确认，文件路径作为转义后的 shell 参数写入；图片不得把二进制内容写入 PTY，并应明确说明未执行粘贴。
- 支持时可启用高性能渲染；初始化失败或运行中丢失图形上下文时必须自动回到内置 DOM 渲染，保持同一 session、模型、视图和输入链路继续可用，不得以重开终端掩盖降级。

搜索控件、链接反馈、粘贴确认、进度和失败状态必须有稳定可访问名称，并保持键盘可操作。视觉位置和状态呈现以 [UI Style Guide](ui-style-guide.md) 为准。

### 启动命令语义

未配置启动命令时，启动入口必须引导用户完成配置。已经配置时，执行启动命令必须：

1. 终止该终端的旧会话。
2. 启动新的终端会话。
3. 清空旧的可见输出。
4. 由 Run 使用当前已提交的启动命令与执行配置启动，并且只执行一次启动命令。

启动过程必须防止重复触发。启动命令不得写入仍在运行的旧项目进程。普通直接启动命令自然结束或被 `Ctrl+C` 中断后，终端必须保留同一交互式 shell 会话并继续接受输入；终端依赖工作流的有限任务仍以真实进程退出码完成调度，受管端口服务仍以受管进程退出完成端口释放。

终端名称、描述、启动命令和执行配置必须作为一个可见定义原子保存；保存失败时不得只提交其中一部分。组合的“启动组合命令”逐个复用同一单终端启动入口，不得建立一套绕过服务端口治理的批量启动实现。

### 重开空终端会话语义

重开空终端会话必须替换旧会话、清空旧输出，并且不得执行已配置的启动命令。入口文案或工具提示必须明确这一差异。

### 终端依赖工作流语义

终端积木通过输入、输出连接点建立有向依赖。连接和任务/服务执行配置随工作区保存；自连接、重复连接和会形成环的连接必须被拒绝。

本节只定义稳定的用户可见交互。上下文归属、执行计划、状态迁移、任务与服务语义、实现入口和验证矩阵统一维护在 [终端依赖工作流](../contexts/run/terminal-workflow.md)。

- “启动命令”仍只运行当前终端，不触发依赖级联。
- 工作流从终端上的“从此处运行流程”发起，只运行该终端及其后代；顶部工具栏不常驻全局运行入口。
- 工作流活动时，窗口右上角持续显示可关闭的活动通知，并提供“停止本次运行”；发起本次运行的根终端将“从此处运行流程”切换为同名兜底动作。顶部工具栏不展示运行状态或流程停止动作。同一工作区同一时间只允许一个活动工作流。
- 工作流状态独立于终端会话状态，使用等待、运行、就绪、成功、失败、阻塞和已停止表达任务进度。
- 任务终端可配置成功退出码和超时；服务终端可选择字面量输出或 TCP 端口作为就绪条件，并配置就绪超时。
- 服务终端可以不管理端口，或显式配置固定、首选、自动端口策略；TCP 就绪必须配置受管端口。直接启动、组合启动和工作流启动使用相同的受管服务语义。
- 多个根节点可以并行；汇合节点等待全部上游成功或就绪；失败只阻塞依赖该节点的后代。
- 折叠终端组合时隐藏成员之间的工作流连线，但不改变连接、计划或运行状态；组合本身不是工作流节点。
- 活动通知随同一个运行 ID 原地更新为就绪、成功、失败或已停止；停止请求进行中必须禁用重复提交。关闭活动通知不得停止工作流，普通状态更新不得将它重新打开，后续失败必须重新提示；切换工作区后再次加载同一运行的既有终态不得重复提示，返回仍在活动的运行时必须恢复活动通知与停止入口，运行在离开期间首次失败时必须提示一次；失败节点和连线仍保留失败或阻塞投影。

### 本地服务端口与实际端点

服务端口配置必须明确表达意图，不根据启动命令猜测框架参数：

- “固定端口”占用时失败，不自动改用其他端口；只有固定策略允许“不注入”。
- “首选端口”优先使用指定端口，冲突时允许自动回退。
- “自动分配”由 Run 选择本机可用端口。
- 动态端口通过用户声明的环境变量或安全命令参数后缀注入；环境变量是界面推荐方式。
- 协议只表达 `HTTP`、`HTTPS` 或 `TCP` 的实际地址语义，不扩大回环监听范围。

受管服务取得实际端点后，终端节点必须以低噪声常驻条展示本次运行的实际地址。地址始终可以复制；只有 Run 仍确认该精确 `sessionId + runId + generation` 属于当前运行且协议为 HTTP/HTTPS 时才显示并执行“打开”，TCP 地址不得交给系统浏览器。首选端口发生回退时必须在同一区域说明原首选端口和实际端口，但正常使用首选或固定端口时不额外制造成功通知。

固定端口冲突、有限分配失败或监听所有权无法确认时，终端节点必须显示结构化冲突反馈。若占用者是当前 cleancode 进程中仍受管的服务，可展示项目、工作区和终端名称并提供定位；只有仍处于已绑定状态的已有服务可以打开。外部或未知监听者只提供编辑端口配置与关闭提示，不展示未经产品化的 PID，也不提供终止外部进程或“停止并重试”。关闭冲突提示只清理表现层反馈，不修改运行状态或端口配置。

受管服务停止时，终端节点必须区分进程退出与端口释放：`releasing` 表示正在等待监听关闭，此时地址可识别但不得打开；`released` 后清除本次端点；`quarantined` 表示清理未确认并已隔离，不得显示为普通“正在使用”或提供打开动作。受管冲突同样必须区分启动中、已绑定、释放中和已隔离 owner；只有已绑定服务可以打开。

实际端点、冲突和所有权都是 Run 事件的易失投影，不写回终端配置。迟到事件只有在项目、工作区、终端和完整运行身份一致时才能更新当前节点；切换工作区、替换会话或结束运行后，旧事件不得覆盖新地址或重新显示旧冲突。

## 终端组合

终端组合是只允许终端成员加入的类型化组合。它用于组织和批量管理开发命令，本身不创建新的 PTY，也不承载终端输出。

终端组合必须遵守：

- 有效组合至少包含两个终端成员。
- 组合动作只能影响该组合的终端成员。
- 解散组合只移除组合关系，必须保留成员终端。
- 折叠和展开只改变展示形态，不得改变成员关系或运行状态。
- 组合成员的运行状态属于成员自身，不得在组合头部重复制造聚合状态。

用户必须能够创建组合、编辑名称、折叠或展开、添加或移出成员、启动成员启动命令、停止成员当前命令、重开成员终端会话和解散组合。

组合编辑模式必须明确表达当前选择、可加入成员、不可加入成员、拖入、移出以及可能导致组合解散的结果。少于两个有效成员时，系统必须阻止形成组合或自动解散组合。

常用组合操作应保持可发现并按运行、成员管理和结构管理形成清晰分组。具体图标、按钮形态和排列属于可演进的表现细节，不是本文的稳定契约。

## Agent 控制台

Agent 控制台是画布内的本地 Agent CLI 交互工作面。它采用节点式画布交互，但不是普通终端积木，也不属于终端组合。cleancode 复用终端技术底座，不引入标签页、Agent 切换器或其他不属于画布模型的信息架构。

Agent 控制台必须：

- 在紧凑头部最左侧显示 Provider 图标，随后显示稳定 Agent 名称；Provider 名称保留为 Tooltip、可访问名称或等效辅助语义，不作为重复的常驻可见文字。Provider 图标只表达品牌身份，不叠加活动圆点、角标或其他状态装饰；Provider 未声明 `activityTracking` 时仍不得从输出频率猜测活动。
- 仅当当前 Provider 声明支持时，在头部几何中心显示“CleanCode MCP”图标开关；身份区域或右侧菜单宽度变化时不得带偏该控件。说明它只授予当前 Agent 查看和修改画布终端、组合、执行配置与依赖工作流的能力。
- 把重命名和删除等低频动作收纳在常驻可见的更多菜单中；支持双击名称就地重命名。
- 承载真实 Provider CLI 的终端输入输出，并支持选择、移动和调整大小。
- Agent launch 只能展示 Provider 自身输出；cleancode 写入长期 shell 的临时脚本路径、状态变量、随机控制 Token 和其他内部启动命令不得出现在屏幕、滚动历史或恢复 snapshot 中。
- 在正文滚动、文本选择和输入时不触发外层画布缩放、平移或节点选择。
- 展示并处理 cleancode 工具审批，在 Agent 修改积木图后刷新当前工作面。
- 切换分支工作区时连接对应 Agent 与分支对话，不串用其他工作区或其他 Agent 状态。
- 应用重开时恢复 Agent 的固定 Provider、数量、名称、位置、大小、MCP 偏好和 Provider 支持的分支对话绑定；Agent terminal 本身当前不跨应用保留。

一个工作区允许拥有零个或多个相同或不同 Provider 的 Agent。首次初始化新工作区时，只有本机检测到 Codex CLI 已安装且 Codex 没有被用户禁用时才创建默认 Codex Agent；其 MCP 初始值读取应用级“新 Agent 默认启用 CleanCode MCP”。否则必须原子持久化一个已初始化的空 Agent 列表，不静默改用其他 Provider，也不得在以后仅因 Codex 安装状态改变而自动补建。用户移除最后一个 Agent 后同样必须保留空状态。创建第二个及后续 Agent 时必须说明它们共享工作区目录、可能同时修改相同文件；需要文件级隔离时应使用不同 worktree。

注册 Provider 目录与“本次可创建”列表是两个不同事实。注册目录是应用支持的完整 catalog，持续为既有 Agent 提供名称、图标、恢复动作、活动状态、MCP 开关和画布指令能力；本机 CLI 后来缺失、版本不足或暂时不可用时，已经持久化的 Agent 仍必须留在工作区并展示相应状态，不能从画布或列表中消失。“本次可创建”列表则是对注册目录执行当前环境检测后的易失结果，只包含状态为 `installed` 的 Provider。

“新建 Agent”使用分段按钮：主按钮直接用应用级默认 Provider 创建，箭头按钮只打开默认 Provider 菜单。菜单仅列出本机当前状态为 `installed` 且没有被用户禁用的 Provider，以图标、名称和单一选中标记表达选择，不展示版本、能力徽章或解释性小字；点击 Provider 只修改后续创建使用的默认值，不在同一步创建 Agent。菜单末尾必须提供 Agent 设置入口，用于查看完整注册 catalog、重新检测、设置默认值和进入未安装 Provider 的配置文档。

用户尚未设置默认值时，首个已安装 Provider 可以作为本次会话的有效默认值；用户明确设置的 Provider 后来不可用时不得静默切换到其他 Provider。没有有效默认值或没有可创建 Provider 时，主按钮必须打开 Agent 设置完成引导，不得创建猜测的 Provider。Provider 发现期间分段按钮保持尺寸稳定并防止提交；创建动作必须在持久化前重新验证当前 Provider 可用性和完整 Project 工作区作用域并阻止重复提交。名称和初始布局由后端原子分配，旧项目或工作区迟到的成功/失败结果不得插入、聚焦或覆盖当前工作面。创建失败使用应用级错误反馈，不重新打开 Provider 选择流程。创建后不得出现切换 Provider 的入口；需要其他 Provider 时新建 Agent。

Provider catalog、图标和能力必须从 registry descriptor 投影，Presentation 不得按 Provider ID 分支。任意新注册且通过 contribution 校验的 Provider 必须无需修改 Presentation 即可进入同一检测、默认选择、设置状态和 Agent 控制台流程，并且只在其 CLI 检测为已安装时成为创建候选；未注册 Provider 必须在应用边界被拒绝，不能由 UI 猜测能力。当前 Codex、Claude Code 和 OpenCode 提供正式会话引用、恢复、launch instructions 与 CleanCode MCP；Claude Code 和 OpenCode 提供精确活动跟踪，Codex 不声明该能力。其余目录项当前只声明基础终端能力，不展示虚假的恢复、活动状态或 MCP 承诺。

Agent 设置必须用单一页面展示应用级默认值和完整目录，不提供模型选择。页面顶部提供 `Yolo / 手动` 权限选择与“新 Agent 默认启用 CleanCode MCP”开关；默认值分别为 `Yolo` 和开启。MCP 默认开关只初始化之后新建的 Agent，不能批量改写已有 Agent，且不支持 MCP 的 Provider 最终仍保持关闭。权限模式和 Provider 启动覆盖在下次启动或重启时生效。

完整目录按 `已安装` 与 `可安装` 分组。已安装项提供启用状态、默认标记、官方文档和可折叠的命令、附加参数、环境变量编辑；可安装项提供检测状态与官方安装文档，不自动执行安装命令。禁用只影响之后的创建候选，不得删除、隐藏或阻止已有 Agent 恢复。设置页不得展示 detector 版本、模型说明、能力说明堆叠或其他与当前决策无关的小字。

启动覆盖必须建立在 Provider registry 的内建 launch metadata 上，按“内建命令与基础参数、权限模式参数、用户覆盖、系统管理参数”合并。用户可以覆盖可执行文件、增加参数和覆盖普通环境变量，但不能移除系统管理的 MCP、session 恢复、遥测、工作目录或安全控制参数。环境变量编辑必须验证 `NAME=value` 结构；无效输入不得持久化。

每个 Agent 必须拥有稳定身份、固定 Provider，以及独立的 Agent terminal、CLI launch、输入输出、审批、MCP 会话和分支对话绑定。移动、选择、重命名或调整大小不得重启 Agent terminal 或 Provider launch。

Agent terminal 使用 Run 的长期 shell、权威终端模型、单调 sequence、snapshot 和 attach/detach 协议，但保持 Agent 自己的画布外观与动作。Provider CLI 自然退出或把 `Ctrl+C` 解释为退出时，只结束当前 Agent launch；Agent 节点、终端屏幕、对话绑定和底层可输入 shell 必须保留。会话结束状态提供“重新启动 Agent”和“新对话”：前者在同一 terminal 中恢复当前对话，后者清除当前分支绑定后启动新对话。两者都不得替换 Agent 身份或影响其他 Agent。

首次连接 Agent terminal、重新启动或新对话 attach 失败时，Agent 控制台必须保留明确错误和同一作用域的重试动作，不得静默显示成空白终端。重复点击重试只能提交一个在途请求；已有 terminal 绑定在替代 attach 失败时继续可输入。用户切换项目或工作区后，旧作用域迟到的 attach 结果不得替换当前 Agent 状态。

Provider-session binding 是独立于 terminal、launch 和 activity 的恢复持久化状态。正式会话引用保存失败时必须提示本次对话仍可继续、但不能承诺下次恢复；不得把仍在运行的 launch 或活动改写为失败，也不得回退到最近会话、其他 Agent 或其他分支的引用。

CleanCode MCP 开关只控制 cleancode 内建画布 MCP。Provider 不支持该能力时不显示开关；支持时只注入本 launch 的 URL、Token、精确工具允许范围和画布语义，不修改用户全局配置或扩大 Shell、文件、Git、网络和其他 MCP 权限。当前 Codex 的 MCP 为 `required`：开启后，当前 registration 完成认证初始化握手前 launch 不得进入 running，失败时本次 launch 失败。Claude Code 和 OpenCode 为 `best_effort`：launch 可以在 MCP 初始化时运行，MCP 失败必须独立告警并保留基础 terminal/launch。切换能力可以替换当前 runtime session/launch 并继续受支持的原对话，必须释放旧端点、临时配置和待审批请求。删除画布对象、解散组合和断开终端依赖始终经过 cleancode 独立审批，不能被 Provider 原生允许范围绕过。

删除终端或解散组合的审批必须明确展示动作、目标名称、目标 ID、影响范围和保留/执行动作，不得只展示机器 ID。断开依赖的审批必须显示上游名称/ID、下游名称/ID、精确连接 ID，并说明只断开这一条依赖，保留两端终端、启动命令、执行配置和组合。审批出现时，画布必须用临时“审批意图连线”连接发起请求的 Agent 与目标对象，并为目标提供区别于普通选择态的审批高亮；折叠组合中的目标终端由组合节点作为可见代理并标明对应待处理内容。断开依赖时，展开端点高亮真实依赖边，折叠端点使用不可交互的临时代理边；两端位于同一折叠组合时不得画自环，只标明组合“包含待断开依赖”。这些投影不得持久化、参与选择、删除或重连。用户可以通过“在画布中查看”同时聚焦 Agent 与所有可见目标，但不得因此改写现有选择。批准后卡片保持执行中状态直到收到实际结果；拒绝、成功或会话取消后移除，执行失败时保留明确错误，目标已不存在时禁用破坏性动作并提示 AI 重新检查画布。多个请求按到达顺序展示，并提示剩余请求数量。

CleanCode MCP 开启时，用户未加限定地说“终端”“整理终端”“终端布局”“终端组合”“终端工作流”或“启动项目的终端组合”，Agent 必须优先理解为当前画布事实并先查看画布；为了确定启动命令可以随后读取仓库，但最终必须通过画布工具创建终端、配置 task/service、建立依赖与组合，排列精确相关终端，再检查工作流计划，不得用直接启动 Shell 进程或创建项目配置代替。当前 MCP 能搭建和检查工作流，但不能启动终端、组合或工作流，Agent 不得把“已搭建”表述为“已运行”。只有明确提到终端源码、Terminal 组件、xterm、PTY 或终端模块实现时，才理解为项目代码。关闭 MCP 时不得向 Provider launch 注入这层画布语义。

移除 Agent 属于用户在当前 Agent 局部菜单中明确发起的破坏性操作，不再要求二次确认。用户选择“移除”后，菜单必须立即关闭并阻止重复提交；系统停止该 Agent、取消其未完成审批并删除 cleancode 中的 Agent 定义和对话绑定，但不会回滚项目文件、删除 Git 提交或影响其他 Agent。菜单用独立分组、危险图标和悬停/焦点状态表达破坏性，不让危险色在默认状态下压过普通动作。

Agent 控制台不得展示终端端口，不得加入终端组合，也不得进入普通终端积木的创建、删除、组合或批量运行流程。

正常状态必须保持静默：Provider CLI 已安装且 launch 正常运行时，Agent 头部和运行区不得常驻展示“已安装”“已连接”、Provider 名称、版本号或同义状态卡；新建 Agent 的默认选择菜单同样不得展示 detector 版本。对于既有 Agent，短时间 CLI 检查不得闪现提示；检查持续较久时才显示中性反馈。首次未取得可用结果必须自动重试一次，只有连续确认找不到当前 Provider 可执行文件时才显示 Provider 对应的未安装和渐进安装帮助；超时、权限或其他命令异常必须显示为可重试的 `temporarily_unavailable`。只有 Provider 声明最低版本且已安装版本不足时才显示 `upgrade_required` 与最低版本；当前仅 Claude Code 声明 `2.1.119`，其他 Provider 不得因虚构的版本门槛显示升级要求。快捷菜单不得列出 `missing`、`upgrade_required` 或 `temporarily_unavailable` 项，这些状态只进入 Agent 设置和既有 Agent 的诊断反馈。

每个 Provider 的 CLI 检查结果属于应用级共享的易失能力快照，不得由每个 Agent 重复维护。Agent 自身运行状态优先于该快照：运行中的 launch 必须保持静默，恢复失败、启动失败和会话结束不得被检查提示遮挡；旧检查结果不得覆盖较新的重试。

对话恢复失败时必须提供紧凑的“重试”和“新对话”动作。新对话只替换当前项目、工作区、Git 分支和当前 Agent 的恢复绑定，不得删除其他 Agent 或其他分支对话。不支持恢复的 Provider 必须诚实降级，不显示虚假的恢复承诺。

工作区往返必须通过 Run 权威模型的完整 snapshot 与连续 sequence 恢复 Agent 屏幕；隐藏期间输出继续进入模型，不依赖某个 renderer xterm 常驻。返回时不得用截断字符串拼接 TUI。Agent 删除、工作区归档、项目移除、默认工作区真实分支替换和应用退出才终止对应 Agent terminal；普通视图卸载只释放可丢弃 surface。

本地 Agent CLI 必须通过应用层用例操作项目、分支工作区、积木图和终端会话，不得直接修改 React 状态、持久化文件、数据库或 PTY 进程。

## 状态与通知行为

用户可见反馈必须遵守：

- 异常状态说明发生了什么，以及用户是否需要采取行动。
- 破坏性操作必须说明影响范围和可恢复性。
- 进行中操作必须防止重复提交或明确处理并发结果。
- 浏览器预览、桌面运行时不可用和真实桌面能力必须清楚区分。

应用级通知属于表现层易失状态，用于反馈已经发生或正在进行且不应占用常驻操作区域的事件。通知必须从窗口右上角弹出，支持信息、成功、警告、错误和活动语义，多条通知可以堆叠并分别关闭；同一事件可以原地更新内容和语义，也可以携带一个与事件作用域一致的上下文动作。异步动作进行中必须显示进行中文案、禁用重复提交，并在完成后恢复或随事件更新。错误通知默认保留到用户关闭，其他通知可以按事件需要自动关闭。通知关闭只移除界面反馈，不得修改事件所属上下文的业务状态、终端输出或诊断事实。通知不跨应用重启恢复，也不得替代节点、连线或对象自身需要长期保留的状态表达。

## 关键验收不变量

- 用户进入项目后可以直接使用画布，而不是先经过营销或欢迎页面。
- 完全退出并重新打开应用后，恢复退出前的当前项目及该项目已提交的当前工作区；项目不可用时回退到首个可用项目。
- 正常退出对运行时清理只等待默认 5 秒；未在预算内完成的 PTY 仍由独立 Provider 持有并继续安全清理，不被误报为已经终止或可恢复。
- 分支工作区切换会同时切换积木图、终端和 Agent 工作面。
- 终端组合不会误操作非成员或非终端对象，解散不会删除成员终端。
- 多个 Agent 控制台保持独立画布节点语义，并与普通终端积木及终端组合隔离。
- Agent 整理工作流后，精确相关终端按依赖关系稳定落在发起 Agent 附近并避开无关对象；并发用户拖动优先，实际变化只触发一次适应视图且不改变选择。
- 小地图能够反映终端、折叠终端组合和 Agent 控制台的位置，但不泄露终端或 Agent 内容。
- 语言切换立即更新第一方界面文案，跨重启恢复显式选择，并且不翻译或改写用户与运行时内容。
- 应用设置全屏覆盖工作区但不重建工作区状态，快捷键修改即时生效、跨重启恢复且不抢占文本或终端输入。
- 侧边栏整体折叠不重建工作台，项目标题点击只折叠该项目的工作区列表且不改变当前工作区；macOS 原生全屏时，侧边栏控件自动贴近窗口最左侧并保持可交互。
- 拖动项目标题可以持久化调整项目顺序，且不会改变当前项目或当前工作区；取消、原位放置或保存失败不会制造新的顺序事实。
- 异常和破坏性结果能够被用户理解，并提供与影响范围一致的后续操作。

## 维护规则

- 稳定产品语义、用户能力、状态含义或交互结果发生变化时，同步更新本文和对应行为测试。
- 局部实现、表现规则和未来方向不得写入本文。
- 新决定替换旧决定时，直接改写旧规则，不保留互相矛盾的描述。
