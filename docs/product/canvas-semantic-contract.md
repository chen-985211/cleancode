# 画布语义契约

## 文档地位

本文是终端、流程、顶层执行单元与组合语义的唯一产品事实来源。BlockGraph、模板、Presentation、CleanCode MCP 初始化说明和 Provider 启动指引不得各自重新定义这些对象或创建条件。

架构分层、状态 owner 和跨上下文依赖仍以[架构文档](../engineering/architecture.md)与[上下文地图](../engineering/context-map.md)为准；流程启动后的调度和状态以[终端依赖工作流](../contexts/run/terminal-workflow.md)为准。

可执行投影位于 [`CanvasExecutionSemantics.ts`](../../src/shared-kernel/domain/policies/CanvasExecutionSemantics.ts)。该纯规则模块不持有图状态，只根据调用方合法提供的终端、依赖和选择计算统一语义结果。

## 统一语言

| 对象         | 定义                                                             |
| ------------ | ---------------------------------------------------------------- |
| 终端         | 最小执行单位。                                                   |
| 流程         | 由依赖连线形成的完整弱连通终端集合，是不可拆分的执行整体。       |
| 顶层执行单元 | 一个独立终端或一条完整流程。                                     |
| 组合         | 可持久存在的独立容器与连线作用域，可包含零个或多个完整执行单元。 |
| 完整流程扩展 | 从任意已命中终端沿无向依赖可达关系取得整条流程。                 |
| 自动结构识别 | 根据顶层执行单元数量识别终端、流程或组合。                       |

## 结构化规则

结构化契约版本为 `2`。两个或以上顶层执行单元仍用于自动识别组合，但不限制用户显式创建的持久化组合容量。对同一组终端与依赖，所有消费者必须得到相同结果：

1. 一个无依赖终端识别为终端。
2. 一个包含两个或以上终端的弱连通依赖分量识别为流程。
3. 两个或以上顶层执行单元识别为组合；这些单元可以是独立终端、完整流程或二者混合。
4. 用户可以显式创建空组合，也可以让组合只容纳一个独立终端或一条完整流程；空组合持续存在，直到用户显式解散或删除。
5. 创建、加入或移出组合成员时，命中流程中的任意终端都扩展为完整流程；一次动作的扩展、占用校验和提交必须原子完成。
6. 普通单击、查看、配置和其他单终端动作仍只作用于当前终端。
7. 模板识别只使用模板快照中的终端和内部依赖，但使用同一顶层执行单元分类规则；单终端、单流程和多顶层单元分别形成终端、流程和组合模板。
8. 从终端节点进入的对象操作使用同一分类结果：无依赖终端保持终端作用域，流程中任意终端扩展为同一完整流程。显式组合节点仍以已经提交的组合成员为作用域。
9. 快捷执行绑定使用同一对象解析：无依赖终端保存终端 ID，流程保存绑定时完整流程的精确终端 ID 集合，组合保存稳定组合 ID；流程不获得新的持久化身份。列表、拖入和右键入口只提交该规范引用，由 BlockGraph 自动占用编号最小的空位。

## 状态与校验所有权

`BlockGraph` 继续拥有终端、连接和组合成员的已提交事实。共享契约提供纯分析结果，不能绕过聚合修改状态。

BlockGraph 在创建与成员调整提交前必须：

1. 校验请求终端存在。
2. 把命中的流程扩展为完整流程。
3. 校验成员没有被其他组合占用。
4. 一次性提交完整成员集合；失败时保持原图不变。

移出完整执行单元后，即使组合只剩一个或零个执行单元也继续存在。恢复旧图时只清理失效成员、重复归组和半流程成员关系；终端、依赖连接、空组合和只包装单流程的组合继续保留。

## 消费者投影

| 消费者              | 复用方式                                                                                                                             |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| BlockGraph 领域规则 | 使用完整流程扩展和成员占用结果兜底创建、加入、移出与恢复                                                                             |
| 模板快照            | 使用统一结构分类决定 `terminal`、`workflow` 或 `combination`                                                                         |
| Presentation        | 使用统一 `canCreateCombination` 结果决定现有创建入口是否可执行                                                                       |
| 节点右键操作        | 从终端节点复用完整流程扩展和分类结果，组合节点使用已提交精确成员                                                                     |
| 快捷执行栏          | 列表、拖入和右键入口复用同一对象解析并生成同一种规范引用                                                                             |
| MCP 初始化说明      | 注入结构化契约生成的规范双语语义段落                                                                                                 |
| Provider 启动指引   | 注入与 MCP 初始化完全相同的规范语义段落                                                                                              |
| MCP 工具协议        | 单终端、单流程和多顶层执行单元使用独立原子创建工具；Agent 应用层用同一分类校验并在输出回显实际结构，组合成员仍由 BlockGraph 再次校验 |

MCP 和 Provider 文案只是契约投影，不是规则 owner。即使 Agent 忽略指引或提交局部流程 ID，BlockGraph 仍必须扩展完整流程、阻止重复归组并保留合法空组合。

## 非目标

- 不引入持久化流程实体或流程 ID。
- 不修改流程启动、组合执行计划、PTY 或 Run 状态机。
- 不规定菜单的具体视觉、定位或动效，也不让右键临时选择成为持久化图事实。
- 不让 Agent、MCP 或 Presentation 成为组合有效性的事实来源。

## 验证不变量

- 单个完整流程的分类结果是 `workflow`，`canCreateCombination` 为 `false`。
- 多个顶层执行单元的分类结果是 `combination`，`canCreateCombination` 为 `true`。
- 组合成员动作从流程任意终端得到相同的完整流程成员集合。
- 右键流程中任意终端得到相同的完整流程对象作用域。
- 三种快捷绑定入口从同一画布对象得到相同的终端、流程或组合引用。
- 模板、UI、MCP 与 Provider 不维护独立的组合阈值或流程定义。
- MCP 初始化说明和 Provider 启动指引包含同一份规范语义文本。
- MCP 原子创建工具与同一输入的规范分类一致；流程工具不能接受单终端或多顶层执行单元。
